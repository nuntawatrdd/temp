CH6 · 2D & 3D Vector Graphics

Bitmap กับ Vector

Bitmapped image เก็บภาพเป็น pixel ทีละจุด เหมาะกับภาพที่มีรายละเอียดเยอะ เช่น ภาพถ่าย แต่ไฟล์ใหญ่และซูมแล้วแตก

Vector graphic เก็บเป็น รูปทรงพื้นฐาน + สมการคณิตศาสตร์ (เส้น สี่เหลี่ยม สามเหลี่ยม วงกลม) ไฟล์เล็ก ซูมเท่าไรก็ไม่แตก เหมาะกับงานที่ต้องการความคมชัดของลายเส้น เช่น logo และ icon

เหตุผลที่ logo เหมาะกับ vector คือ “ความคมชัดของลายเส้นมีความสำคัญ” ไม่ใช่เพราะไฟล์เล็ก ไม่ใช่เพราะไม่ต้องบีบอัด และไม่ใช่เพราะสีหลากหลาย

Coordinates, Points, Vectors

  • Cartesian coordinate อ้างอิงแกน x, y ที่ตัดกันที่ origin (0,0)
  • Point ระบุตำแหน่งแน่นอน เขียนเป็น tuple (x, y) เช่น (3,2) คือไปขวา 3 ขึ้น 2
  • Vector เกิดจากการลากเส้นระหว่าง 2 จุด บอกการกระจัด มีคุณสมบัติ 2 อย่าง: direction (ทิศทาง) และ magnitude (ขนาด)
  • Pixel coordinate บนจอ origin อยู่ มุมซ้ายบน และ แกน y ชี้ลง

Vector ไม่ได้กำหนดจาก “ระยะห่างจากจุดศูนย์กลาง” ส่วนในพิกัด pixel จุดที่อยู่ขวา 4 ลง 2 คือ (4, 2) ไม่ใช่ (4, −2)

2D Modeling & Rendering

Vector เก็บ “คำสั่งสร้างรูปทรง” เช่น เส้นตรงเก็บจุดปลาย (x₀,y₀) และ (x₁,y₁) วงกลมเก็บจุดศูนย์กลางกับรัศมี ซึ่งจุดบนวงกลมต้องเป็นไปตาม (x−x₀)² + (y−y₀)² = r²

การแปลง vector ให้กลายเป็น pixel เพื่อแสดงบนจอ เรียกว่า rasterization มี 3 ขั้น:

  1. แปลงระบบพิกัดคณิตศาสตร์ให้เข้ากับจอ (เริ่มที่มุมซ้ายบน)
  2. คำนวณว่า pixel ไหนอยู่บนเส้น ด้วย Bresenham algorithm แล้วระบายสี
  3. ปัดเศษให้ใกล้ pixel ที่สุด

Bezier Curve

เส้นโค้งที่ควบคุมความโค้งด้วย control points

ชนิดControl pointsลักษณะ
Linear (degree 1)2 จุด (P0, P1)เส้นตรง P = (1−t)P0 + tP1, 0 ≤ t ≤ 1 (เหมือน linear interpolation)
Quadratic (degree 2)3 จุด (P0, P1, P2)โค้งพื้นฐาน P1 ดึงความโค้ง
Cubic (degree 3)4 จุด (P0–P3)ยืดหยุ่นสุด P1, P2 เป็น direction lines ควบคุมโค้งที่จุดต้น/ปลาย

ในรูปที่มี P0, P1, P2, Q0, Q1, R0, B — control points คือ P เท่านั้น ส่วน Q, R, B เป็นจุดที่คำนวณระหว่างทาง (B คือจุดบนเส้นที่ค่า t นั้น เช่น t = .25 = 1 ใน 4)

Properties & Transformations

เส้นขอบ (stroke)

มีสี ความหนา รูปแบบ และ caps: Butt ตัดพอดีปลาย · Rounded เพิ่มครึ่งวงกลมที่ปลาย · Projecting ตัดเหลี่ยมแต่ยื่นเลยปลาย

สีพื้น (fill)

สีและความโปร่งใส, Gradient (Linear = เส้นตรง, Radial = จากศูนย์กลางออกด้านนอก, Angle = กวาดรอบจุด) และ Texture

การแปลงรูปทรง

Affine transforms (รักษาสมบัติเชิงเรขาคณิตสำคัญไว้) มี 5 แบบ: Translation, Rotation, Scale, Reflection, Shearing (skew)

Non-affine: Projective transform ทำให้ภาพมีมิติลึก (perspective)

“ข้อใดไม่เข้าพวกกับ transformation” → projective transform (เพราะเป็น non-affine)

Boolean operators

A OR B (union) · A AND B (intersection — พื้นที่น้อยสุด เหลือเฉพาะส่วนซ้อน) · A XOR B (ส่วนที่ไม่ซ้อน) · A not B · B not A

3D Modeling

2D อยู่บนระนาบเดียว ส่วน 3D ใช้ระบบพิกัด 3 มิติ (x, y, z)

การสร้างวัตถุ 3D

  • รวม 3D primitives (กล่อง ทรงกลม ทรงกระบอก) + แปลงรูปทรง + Boolean
  • สร้างจาก 2D: Extrusion ดึงรูป 2D ให้มีความหนา (เช่น เฟือง) · Lathe/Lathing หมุนเส้นโครงร่างรอบแกน (เช่น หมวก แจกัน)

Polygon mesh

ผิวของวัตถุเก็บเป็น polygon (มักเป็น △ หรือ □) ต่อกัน องค์ประกอบ: Vertex (จุดมุม) · Edge (เส้นขอบเชื่อม vertex) · Face (พื้นผิวที่ล้อมด้วย edge)

ข้อดี: ยืดหยุ่น (ประมาณรูปทรงได้แทบทุกแบบ) · polygon มาก = ละเอียดมาก · แก้ไขระดับ polygon ได้

Parametric surface (เช่น NURBS) เหมาะกับผิวโค้งเรียบ แต่สุดท้ายต้องแปลงเป็น polygon mesh ก่อน render

ขั้นสุดท้าย: กำหนด material (สี ความสว่าง specular roughness metallic) และ texture (แปะภาพ 2D บนผิว)

3D Rendering

Rendering คือการแปลง 3D model เป็นภาพ 2D จากมุมมองกล้องเสมือน โดยจำลองว่าแสง วัตถุ และกล้องมีปฏิสัมพันธ์กันอย่างไร

  • Specular reflection ผิวมันเรียบ มุมตกกระทบ = มุมสะท้อน เกิด highlight จุดสว่างจ้า
  • Diffuse reflection ผิวหยาบ แสงกระจายหลายทิศ (เช่น ไม้)

ขั้นตอน real-time rendering (ช่วยจำ: “Per–Vi–Shade”):

1. Perspective projection→2. Visibility check→3. Shading
  1. Projection map polygon 3D ลงระนาบ 2D ของกล้อง
  2. Visibility check หาว่าด้านไหนถูกบัง (ซ่อนเส้นด้านหลัง)
  3. Shading คำนวณสี: Flat (แต่ละ polygon สีเดียว เห็นเหลี่ยม) · Gouraud (ไล่สีตาม vertex เนียนขึ้น) · Phong (สมจริงที่สุด highlight สวย)

รูป wireframe 2 รูปที่ต่างกันแค่ “เห็นเส้นด้านหลังหรือไม่” → visibility check
ทรงกลม 2 ลูกที่ต่างกันแค่ “เหลี่ยม vs เนียน” → shading

Animation คืออะไร

Animate แปลว่า “ทำให้มีชีวิต” — animation คือการทำให้ภาพวาดหรือวัตถุนิ่งดูมีชีวิตผ่านภาพเคลื่อนไหว อาศัย persistence of vision

Interpolation Functions

การสร้าง in-between frames ต้องใช้ interpolation function คำนวณ ตำแหน่ง รูปร่าง การหมุน และสี ของวัตถุในเฟรมระหว่างกลาง

Vector object tween ได้โดยตรง ส่วน bitmap ต้องทำผ่าน proxy object · ฟังก์ชันยอดนิยมคือ Bezier curve (อีกแบบคือ Hermite curve)

“บทบาทของ interpolation function” มีตัวเลือก รูปร่าง / ตำแหน่ง / การหมุน / สี → ตอบ ถูกทุกข้อ

Continuity (การต่อเส้นโค้ง)

Bezier หลายช่วงต่อกันเรียกว่า spline ที่จุดต่อพิจารณาความต่อเนื่อง 2 แบบ

ระดับG (Geometric) — สนใจแค่ทิศทางC (Parametric) — ทิศทาง + ขนาด
0G0 = C0 : จุดปลายมาบรรจบกันพอดี
1G1 (tangency) : ทิศทางของ tangent (1st derivative) ตรงกันC1 : tangent (velocity) เท่ากันทั้งทิศทางและขนาด
2G2 (curvature) : ทิศทางของ 2nd derivative ตรงกันC2 : 2nd derivative (acceleration) เท่ากันทั้งทิศทางและขนาด

Cx เข้มงวดกว่า Gx เสมอ (Cx ⇒ Gx) และระดับสูงรวมระดับต่ำไว้ด้วย (G2 ⇒ G1 ⇒ G0)

“G1 ไม่แตกต่างจาก C1” → ผิด (G1 สนแค่ทิศ, C1 สนทั้งทิศและขนาด)

“ข้อใดไม่เกี่ยวกับการตรวจ G2” → ขนาด (magnitude) ของ 1st derivative เพราะ G ไม่สนขนาด

“ข้อใดไม่เกี่ยวกับการตรวจ C2” (C0, C1, 1st, 2nd derivative) → ทุกข้อเกี่ยวข้องหมด

รูป Broken / Aligned / Mirrored → C0, C0, C1

Interpolation-based Animation

ใช้ interpolation เพื่อ 3 อย่าง: กำหนด motion path · ควบคุม ความเร็ว (speed control) · กำหนดการเปลี่ยนรูปร่างตามเวลา

Speed control ด้วย curve แยก

  1. Normalize ระยะทางทั้งหมดบน motion path ให้อยู่ช่วง 0 ≤ s ≤ 1
  2. Speed curve S(t) รับเวลา t → ให้ระยะทาง (arc length) s เช่น S(t) = (2−t)t
  3. เปิด arc length table หา parameter u = U(s)
  4. แทนค่าใน curve ได้ตำแหน่ง p = P(U(S(t)))

ตาราง u: 0.15 → s 0.230, 0.20 → s 0.320, 0.25 → s 0.400 ถ้า S(t₀) = 0.32 ตำแหน่งคือ P(0.2) (ไม่ใช่ P(0.32) — 0.32 คือระยะทาง ไม่ใช่ parameter)

Motion animation (motion tween)

สร้าง in-between สำหรับ position, scale, rotation หลักการที่เกี่ยว: slow in & slow out

  • Ease-in เริ่มช้า แล้วเร็วขึ้นเรื่อย ๆ
  • Ease-out เริ่มเร็ว แล้วชะลอตอนจบ

Shape animation (shape tween)

เปลี่ยน property (รูปทรง สี ความโปร่งใส texture) จาก key frame แรกไปสุดท้าย หลักการที่เกี่ยว: squash and stretch — ปริมาตรคงที่ (ยืดสูงก็ต้องผอมลง)

Morphing animation

แปลงภาพต้นทางเป็นภาพปลายทาง (2D image metamorphosis) ใช้ vector เป็น proxy ผ่าน Free Form Deformation (FFD)

1. Point mapping→2. Image warping→3. Cross-dissolve

วาง key grid บนภาพทั้งสอง → interpolate grid ตามเวลา → warp ภาพทั้งสองตาม grid กลาง → เฟดสีผสมกัน

Advanced Animation

  • Human figure animation ใช้ hierarchical modeling (child สืบทอดการเปลี่ยนแปลงจาก parent เช่น สะโพกขยับ ต้นขาตาม) + Forward kinematics (เริ่มจาก root เช่น หมุนไหล่ แขนตาม) / Inverse kinematics (เริ่มจากปลาย/leaf เช่น จับมือไปตำแหน่งหนึ่ง แล้วคำนวณข้อศอก)
  • Physically-based animation จำลองธรรมชาติด้วยโมเดลฟิสิกส์ เช่น ใบไม้ไหว น้ำไหล คลื่นทะเล เปลวไฟ ฝูงนก ใช้กับการเคลื่อนไหวซับซ้อน หรือ real-time interactive
  • Facial animation & motion capture จับสีหน้าคนจริงไปควบคุมตัวละคร

CH8 · Sound

คุณสมบัติเสียง การแปลงเป็นดิจิทัล การประมวลผล การบีบอัด การสังเคราะห์ และ stereo/3D audio

Sound Basics

Sound = การสั่นสะเทือนที่เดินทางเป็นคลื่นผ่านตัวกลาง (ก๊าซ ของเหลว ของแข็ง) · Audio = เสียงในรูปสัญญาณไฟฟ้า มี analog และ digital · Audible sound = 20 Hz – 20,000 Hz

คุณสมบัติของเสียง

  • Amplitude การบีบ/คลายมากน้อย (pressure) = (max − min)/2 แปรตามพลังงาน ลดลงตามระยะทาง
  • Frequency / wavelength อัตราการบีบคลาย (Hz) · wavelength = ระยะระหว่างยอด · c = f·λ (f กับ λ แปรผกผัน)
  • Spectrum ระดับสัญญาณที่ความถี่ต่าง ๆ ที่ประกอบเป็นเสียงนั้น — ทำให้แยกเสียงเครื่องดนตรีต่างชนิดได้
  • Loudness หน่วย decibel

“ข้อใดไม่ใช่คุณสมบัติของ sound” → Digital or Analog · แยกเสียงไวโอลินกับแซกโซโฟน → Spectrum

Frequency analysis

Fourier: สัญญาณใด ๆ สร้างได้จาก sine wave หลายความถี่รวมกัน · Fourier transform แยกสัญญาณออกเป็นความถี่ · Spectrum = กราฟแกนนอนความถี่ แกนตั้ง amplitude/power (power ∝ amplitude²) · นำไปสู่ RGB, image compression ฯลฯ

Decibel

dB = 10·log(I/I₀), I₀ = 10⁻¹² · ทุก +10 dB ≈ ดังขึ้น 2 เท่า และพลังงาน 10 เท่า เช่น ถนน 85 dB, คอนเสิร์ต 105 dB (มากกว่า 20 dB = 100 เท่าของพลังงาน) · เสียงดิจิทัลใช้ dBFS ค่าสูงสุด = 0 dBFS

Recording & Digitization

ไมโครโฟนแปลงแรงดันคลื่นเสียง → สัญญาณไฟฟ้า (analog audio)

Mic→Audio interface: ADC→คอมพิวเตอร์→DAC→ลำโพง/หูฟัง
  • Dynamic range = เสียงดังสุด − เบาสุด
  • Clipping = distortion เมื่อสัญญาณเกินระดับสูงสุดที่ ADC รับได้ (0 dBFS) → แก้โดยตั้ง analog gain ให้ไม่สูงเกิน
  • Sampling rate จำนวน sample/วินาที · Bit depth จำนวนบิตต่อ sample
  • Quantization noise ความต่างระหว่างค่า analog จริงกับค่าดิจิทัล (เฉลี่ย ½)
  • SQNR ≈ 6.02N + 1.76 dB → ทุก 1 bit เพิ่ม ≈ 6 dB เช่น N = 10 → ≈ 60 dB, N = 16 → ≈ 98 dB
  • Dithering เติม noise เล็กน้อยเพื่อลดผลของ quantization (เสียงกระด้างน้อยลง) ใช้ตอน re-quantize ลด bit depth เช่น 24 → 16 bit

Reverb

เสียงตรง + เสียงสะท้อน ทำให้รับรู้พื้นที่/บรรยากาศ (soundscape) ถ้าเสียงสะท้อนมาช้ามากจะกลายเป็น echo

เสียงสะท้อนที่ “ซับซ้อนที่สุด” → Late reverberant sound · “ขนาดห้อง” มาจากองค์ประกอบใดมากที่สุด → Early reflection

Audio Compression

Lossless

เก็บแค่ผลต่างระหว่างค่าจริงกับค่าที่ทำนาย (ง่ายสุดคือทำนายว่าเท่ากับ sample ก่อนหน้า) ผลต่างเล็ก → ใช้บิตน้อย เช่น DPCM, FLAC, ALAC, Dolby TrueHD ขนาดเหลือ 40–60%

Lossy

อาศัย psychoacoustics: ความไวการได้ยินต่างกันในแต่ละความถี่ (threshold of hearing) และ masking

  • Frequency masking เสียงดังทำให้เสียงเบาที่ความถี่ใกล้เคียงไม่ได้ยิน
  • Temporal masking เสียงดังบังเสียงที่เกิดก่อน/หลังในช่วงเวลาสั้น ๆ

ขั้นตอน (แบบ MP3): แบ่ง 32×12 samples ผ่าน 32 band-pass filters → จัดสรรบิตแต่ละแบนด์ตาม threshold (เก็บเฉพาะเสียงที่สูงกว่า threshold, เพิ่มบิตถ้า quantization noise ดังจนได้ยิน) → บันทึกจำนวนบิต scale factor และข้อมูล · อัตราบีบอัด ≈ 10:1 เช่น MP3, AAC (มาตรฐานมือถือ Apple Music YouTube), Vorbis (open source)

Codec ≠ file format (M4A, OGG เป็น format)

DPCM / Dolby TrueHD / ALAC / FLAC / MP3 ข้อใดไม่เข้าพวก → MP3 (lossy)
“ข้อใดไม่เกี่ยวกับ lossy” (threshold, band-pass, temporal, frequency masking) → ทุกข้อเกี่ยวข้องหมด (band-pass filter ใช้แบ่งเสียงเป็น 32 แบนด์ จึงเกี่ยวข้อง)
“เคยได้ยินเสียงหนึ่ง แต่ไม่ได้ยินเมื่อมีเสียงความถี่ใกล้เคียงดังขึ้น” → Frequency masking

Character Encoding

การกำหนดตัวเลขให้ตัวอักษรเพื่อเก็บ/ส่ง/ประมวลผลในคอม

ASCII

มาตรฐานแรกที่แพร่หลายบน PC (ก่อนหน้ามี EBCDIC บน IBM) ใช้ 7 bits (0–127) · 1 byte = 8 bit จึงเหลือ 128–255 → Extended ASCII / code page สำหรับภาษาอื่น เช่น ไทย (windows-874)

ปัญหา: ถ้าใช้ code page ไม่ถูกจะเห็นตัวอักษรขยะ (ÔÇµÇ…) · ที่ไม่พอสำหรับจีน/ญี่ปุ่น · รองรับหลายภาษาได้จำกัด

Unicode

มาตรฐานสากล รองรับทุกภาษา ไม่ต้องระบุ code page มี emoji แยกเป็น 3 ส่วน:

  1. Coded character set → ให้เลขไม่ซ้ำแก่ทุกตัว = code point เขียน U+hex เช่น U+0E01 = ก
  2. map code point เป็น code units ขนาดคงที่
  3. encode code units เป็นลำดับ octets (bytes)

Code point แบ่งเป็น 17 planes ละ 65,536 (2¹⁶) · Plane 0 = BMP สำคัญสุด (มีภาษาไทย)

Typography Basics

1. ภาพบิตแมปกับกราฟิกแบบเวกเตอร์

คอมพิวเตอร์เก็บภาพได้ 2 วิธีที่ต่างกันโดยสิ้นเชิง

ภาพบิตแมป (bitmapped image หรือ raster image) เก็บภาพเป็นตารางของจุดสีเล็ก ๆ จำนวนมาก แต่ละจุดเรียกว่าพิกเซล (pixel) คอมพิวเตอร์จำแค่ว่าพิกเซลแต่ละจุดมีสีอะไร เหมือนภาพโมเสกที่ต่อจากกระเบื้องชิ้นเล็ก ๆ ภาพถ่ายจากกล้องเป็นภาพบิตแมป ข้อเสียคือเมื่อขยายภาพมาก ๆ จะเห็นพิกเซลเป็นสี่เหลี่ยมชัดขึ้น ที่เราเรียกว่า “ภาพแตก” และไฟล์มีขนาดใหญ่เพราะต้องเก็บทุกจุด

กราฟิกแบบเวกเตอร์ (vector graphic) ไม่ได้เก็บจุดสี แต่เก็บคำสั่งวาดรูปทรงด้วยรูปเรขาคณิตพื้นฐาน เช่น เส้นตรง เส้นโค้ง สี่เหลี่ยม วงกลม พร้อมตัวเลขที่ใช้กำหนดรูปทรงนั้น เช่น “วงกลม จุดศูนย์กลางอยู่ที่ (50, 50) รัศมี 20 สีแดง” ทุกครั้งที่จะแสดงผล คอมพิวเตอร์จะคำนวณและวาดใหม่ตามขนาดที่ต้องการ ภาพจึงคมชัดทุกขนาด ไม่แตกเมื่อขยาย และไฟล์เล็กมาก

ภาพบิตแมปกราฟิกเวกเตอร์
เก็บอะไรสีของพิกเซลทุกจุดรูปทรงเรขาคณิตและสมการ
เมื่อขยายภาพแตก เห็นเป็นจุดสี่เหลี่ยมคมชัดเหมือนเดิม
ขนาดไฟล์ใหญ่ (แม้บีบอัดแล้วก็ยังใหญ่กว่า)เล็ก
เหมาะกับภาพถ่ายธรรมชาติ ภาพคน ภาพวิว ที่มีรายละเอียดและเฉดสีมากโลโก้ ไอคอน สัญลักษณ์ ป้ายบอกทาง งานลายเส้นที่ขอบต้องคม

ทำไมภาพถ่ายไม่ใช้เวกเตอร์ เพราะภาพธรรมชาติมีพื้นผิว (texture) และเฉดสีละเอียดจำนวนมาก ถ้าจะวาดด้วยรูปเรขาคณิตต้องใช้รูปทรงจำนวนมหาศาลจนไฟล์ใหญ่กว่าเดิม บิตแมปจึงเหมาะกว่า

เหตุผลที่โลโก้ควรเก็บเป็นเวกเตอร์ คือ ความคมชัดของลายเส้นมีความสำคัญ ไม่ใช่เพราะไฟล์เล็ก ไม่ใช่เพราะไม่ต้องบีบอัด และไม่ใช่เพราะเก็บสีได้หลากหลาย

2. ระบบพิกัด จุด และเวกเตอร์

มนุษย์มองเห็นรูปทรงด้วยตา แต่คอมพิวเตอร์เข้าใจแค่ตัวเลข จึงต้องมีระบบพิกัด (coordinate system) เป็นสะพานแปลงรูปทรงให้เป็นตัวเลข เมื่อรูปทรงกลายเป็นตัวเลขแล้ว เราจะเก็บลงไฟล์ได้ คำนวณได้ (เช่น หาความยาว หาพื้นที่) และเขียนโปรแกรมสั่งให้หมุน ย่อ ขยาย หรือเลื่อนได้

ระบบพิกัดคาร์ทีเซียน (Cartesian) มีแกนนอน x และแกนตั้ง y ตัดกันที่จุดกำเนิด (origin) ซึ่งมีพิกัด (0, 0)

  • จุด (point) บอกตำแหน่งที่แน่นอนเพียงตำแหน่งเดียว เขียนเป็นคู่ตัวเลข (x, y) เรียกว่า tuple เช่น (3, 2) คือไปทางขวา 3 หน่วย และขึ้นบน 2 หน่วยจากจุดกำเนิด จุดไม่มีขนาดและไม่มีทิศทาง
  • เวกเตอร์ (vector) บอกการกระจัด คือการเคลื่อนจากจุดหนึ่งไปอีกจุดหนึ่ง ถ้ามีจุด A (x₁, y₁) และจุด B (x₂, y₂) เวกเตอร์จาก A ไป B คือ (x₂ − x₁, y₂ − y₁) เวกเตอร์มีคุณสมบัติ 2 อย่าง คือ ทิศทาง (direction) ว่าไปทางไหน และ ขนาด (magnitude) ว่าไปไกลเท่าไร

พิกัดพิกเซลกับพิกัดจริง

พิกัดพิกเซล (pixel coordinates) ใช้บนหน้าจอหรือไฟล์ภาพ จุด (0, 0) อยู่ที่มุมบนซ้าย ค่า x เพิ่มเมื่อไปทางขวา และค่า y เพิ่มเมื่อลงด้านล่าง (ตรงข้ามกับคณิตศาสตร์) ค่าพิกัดเป็นจำนวนเต็มเท่านั้น เพราะใช้นับช่องพิกเซล

พิกัดจริง (real coordinates) ใช้จำนวนจริงที่มีทศนิยมได้ เช่น (2.35, 2.95) จึงระบุตำแหน่งที่อยู่ระหว่างช่องพิกเซลได้ ใช้ตอนคำนวณรูปทรงทางคณิตศาสตร์

Vector ไม่ได้กำหนดจาก “ระยะห่างจากจุดศูนย์กลาง” · ในพิกัดพิกเซล จุดที่อยู่ขวา 4 ช่อง ลงล่าง 2 ช่อง คือ (4, 2) ไม่ใช่ (4, −2) เพราะแกน y ชี้ลง

3. การสร้างโมเดลและการเรนเดอร์ภาพ 2 มิติ

การวาดกราฟิกเวกเตอร์ลงจอมี 2 ขั้น

ขั้นที่ 1 Modeling (สร้างโมเดล) คือการนิยามรูปทรงด้วยคณิตศาสตร์ เหมือนเขียนแบบแปลนบ้าน เส้นตรงเก็บแค่จุดปลาย 2 จุด คือ (x₀, y₀) และ (x₁, y₁) วงกลมเก็บแค่จุดศูนย์กลาง (x₀, y₀) กับรัศมี r เพราะจุดทุกจุดบนเส้นรอบวงต้องเป็นไปตามสมการ (x − x₀)² + (y − y₀)² = r² อยู่แล้ว

ขั้นที่ 2 Rendering หรือ Rasterization (เรนเดอร์) คือการนำแบบแปลนทางคณิตศาสตร์มาวาดลงบนตารางพิกเซลของจอจริง ปัญหาคือโมเดลใช้จำนวนจริงที่ต่อเนื่อง แต่จอใช้จำนวนเต็มที่ไม่ต่อเนื่อง จึงต้องจับคู่ (map) ระหว่างสองระบบ ทำ 3 ขั้นย่อย:

  1. แปลงระบบพิกัดคณิตศาสตร์ให้เป็นระบบพิกัดของจอ (เริ่มที่มุมบนซ้าย แกน y ชี้ลง)
  2. คำนวณว่าพิกเซลใดอยู่บนรูปทรง แล้วระบายสีพิกเซลนั้น
  3. ปัดเศษค่าที่คำนวณได้ให้ตรงกับพิกเซลที่ใกล้ที่สุด

Bresenham’s algorithm เป็นตัวอย่างวิธีวาดเส้นตรง: เริ่มจากปลายด้านหนึ่ง แล้วขยับไปตามแกน x ทีละ 1 พิกเซล แต่ละตำแหน่ง x คำนวณค่า y ตามสมการเส้นตรง ค่า y ที่ได้มักเป็นทศนิยม เช่น 3.4 จึงปัดให้เป็นแถวที่ใกล้ที่สุด (แถว 3) แล้วระบายสีพิกเซลนั้น ทำซ้ำจนถึงปลายอีกด้าน

เวกเตอร์ต้องถูก rasterize เป็นพิกเซลก่อนแสดงผลเสมอ เพราะจอแสดงได้แค่พิกเซล — ข้อนี้ออกสอบว่า “กระบวนการแปลง vector ให้แสดงผลได้เรียกว่า” ตอบ rasterization

4. เส้นโค้งและ Bezier curve

เส้นโค้ง (curve) คือเส้นที่ไม่จำเป็นต้องตรง สำคัญมากในงานออกแบบทั้งของจริง (ตัวรถยนต์ เครื่องบิน เรือ) และงานดิจิทัล (โลโก้ การ์ตูน อนิเมชัน) เพราะช่วยสร้างรูปร่างที่สวยและเป็นธรรมชาติ

Bezier curve เป็นเส้นโค้งทางคณิตศาสตร์ที่นิยมที่สุด เพราะเรียบ (smooth) และควบคุมง่าย แค่ขยับจุดควบคุม (control points) รูปร่างเส้นก็เปลี่ยน แบ่งตาม degree (ระดับ):

Linear Bezier (degree 1) — ใช้ 2 จุดควบคุม

สมการ P(t) = (1 − t)·P0 + t·P1 โดย 0 ≤ t ≤ 1 ค่า t เหมือน “ตัวบอกความคืบหน้า” เมื่อ t = 0 จุด P อยู่ที่ P0 เมื่อ t = 1 อยู่ที่ P1 เมื่อ t = 0.5 อยู่กึ่งกลางพอดี ผลลัพธ์เป็นเส้นตรง และสมการนี้คือ linear interpolation (การหาค่าระหว่างกลางแบบเส้นตรง) นั่นเอง

Quadratic Bezier (degree 2) — ใช้ 3 จุดควบคุม

สมการ P(t) = (1 − t)²P0 + 2(1 − t)t·P1 + t²P2 เส้นเริ่มที่ P0 จบที่ P2 และถูกดึงเข้าหา P1 แต่ไม่ผ่าน P1 เป็นเส้นโค้งพื้นฐาน

Cubic Bezier (degree 3) — ใช้ 4 จุดควบคุม

สมการ P(t) = (1 − t)³P0 + 3(1 − t)²t·P1 + 3(1 − t)t²·P2 + t³P3 นิยมที่สุดในงานกราฟิก P0 คือจุดเริ่ม P3 คือจุดจบ ส่วน P1 และ P2 ควบคุมทิศทางและความโค้ง โดย P1 − P0 บอกทิศทางและ “ความเร็ว” ของเส้นที่จุดเริ่ม และ P3 − P2 บอกที่จุดจบ ในโปรแกรมกราฟิก P1, P2 จะแสดงเป็น “ก้านจับ” (direction lines หรือ handles) ให้ลาก

จุด Q, R, B ในรูปคืออะไร

ในรูปจากสไลด์ จะเห็นจุด Q0, Q1, R0, B ด้วย จุดเหล่านี้ไม่ใช่ control points แต่เป็นจุดที่คำนวณระหว่างทางเพื่อหาว่าเส้นโค้งผ่านตรงไหนที่ค่า t หนึ่ง เช่น t = 0.25: หา Q ที่อยู่ 1/4 ของแต่ละเส้นระหว่าง P → หา R ที่อยู่ 1/4 ของเส้นระหว่าง Q → จุด B ที่อยู่ 1/4 ของเส้นระหว่าง R คือจุดบนเส้นโค้งจริง

Control points คือ จุด P เท่านั้น · รูปที่มี P0–P3 คือ cubic, 4 control points, degree 3 และ B ที่ t = .25 คือ 1 ใน 4 → ตอบ ถูกทุกข้อ

การต่อ Bezier หลายเส้นเข้าด้วยกัน

เราต่อ Bezier หลายช่วงเป็นเส้นยาวได้ (เรียกว่า spline) และถ้าปลายเส้นสุดท้ายต่อกลับมาที่จุดเริ่ม จะได้เส้นปิด (closed curve) ซึ่งใช้สร้างรูปทรงซับซ้อนอย่างโลโก้ ที่จุดต่อมี 3 แบบ:

  • Broken — ก้านจับสองฝั่งชี้คนละทิศ เส้นแค่แตะกันแต่เกิดมุมหัก → C0
  • Aligned — ก้านจับอยู่แนวเดียวกัน (ทิศเดียวกัน) แต่ยาวไม่เท่ากัน ดูเรียบด้วยตา แต่ตามนิยาม C ยังไม่ถึง C1 → C0 (ถ้านับแบบ G จะได้ G1)
  • Mirrored — ก้านจับอยู่แนวเดียวกันและยาวเท่ากัน ทั้งทิศและขนาดเท่ากัน → C1

โน้ตใน Notion ของคุณเขียนว่า Aligned เป็น C1 แต่เฉลยในแบบฝึกหัดจริงคือ Broken, Aligned, Mirrored = C0, C0, C1 เพราะ C1 ต้องการให้ขนาดเท่ากันด้วย ให้ตอบตามเฉลย

5. คุณสมบัติและการปรับแต่งวัตถุกราฟิก

เส้นขอบ (border หรือ stroke)

กำหนดสี ความหนา รูปแบบเส้น (ทึบ เส้นประ เส้นจุด) รูปมุมตรงที่เส้นสองเส้นมาต่อกัน (joins) และรูปปลายเส้น (caps)

Joins (มุมต่อเส้น) เห็นชัดเมื่อเส้นหนา มักมี 3 แบบ (ชื่อแบบมาตรฐาน ไม่ได้อยู่ในสไลด์): miter ต่อขอบยื่นออกไปจนเป็นมุมแหลม · round มุมโค้งมน · bevel ตัดมุมออกเป็นเส้นเฉียง

Caps (ปลายเส้น) มี 3 แบบ:

  • Butt cap — ตัดตรงพอดีที่จุดปลาย
  • Rounded cap — เติมครึ่งวงกลมที่ปลาย ทำให้ปลายมน
  • Projecting cap — ตัดเหลี่ยมแต่ยื่นเลยจุดปลายออกไปเล็กน้อย

การระบายพื้นที่ด้านใน (fill)

กำหนดสี ความโปร่งใส ลวดลาย (texture) และ gradient (การไล่สี) ซึ่งมี 3 แบบ: Linear ไล่สีตามแนวเส้นตรง · Radial ไล่สีจากจุดศูนย์กลางออกไปด้านนอกเป็นวง · Angle ไล่สีโดยกวาดไปรอบจุดศูนย์กลางเหมือนเข็มนาฬิกา

การแปลงรูปทรง (transformation)

Affine transformation คือการแปลงที่รักษาสมบัติสำคัญทางเรขาคณิตไว้ ได้แก่ เส้นที่ขนานกันยังขนานกัน และอัตราส่วนระยะทางยังเท่าเดิม มี 5 แบบ (ช่วยจำ “Tran–Ro–Scale–Re–Shear”):

  1. Translation — เลื่อนตำแหน่ง โดยไม่หมุนและไม่เปลี่ยนขนาด
  2. Rotation — หมุนรอบจุดที่กำหนด
  3. Scale — ย่อหรือขยายตามแกน x และ y
  4. Reflection — สะท้อนข้ามเส้น เหมือนส่องกระจก
  5. Shearing (skew) — เลื่อนด้านหนึ่งของวัตถุไปทางหนึ่ง ทำให้รูปเอียง เหมือนดันกล่องลูกบาศก์จากด้านข้าง

Non-affine transformation ไม่รักษาเส้นขนาน ตัวอย่างคือ projective transform ที่ทำให้ภาพดูมีความลึก เหมือนรางรถไฟที่ดูเหมือนบรรจบกันที่ขอบฟ้า

ข้อใดไม่เข้าพวก (rotation, translation, shearing, scale, projective) → projective transform เพราะเป็น non-affine

Boolean operators

นำวัตถุ 2 ชิ้นมารวมกันด้วยตรรกะ ได้วัตถุใหม่:

  • OR (union) — รวมพื้นที่ทั้งหมดของ A และ B
  • AND (intersection) — เหลือเฉพาะส่วนที่ซ้อนทับกัน จึงได้พื้นที่น้อยที่สุด
  • A not B (difference) — พื้นที่ของ A ที่ตัดส่วนที่ทับกับ B ออก
  • XOR — พื้นที่ของทั้งสองชิ้น ยกเว้นส่วนที่ทับกัน

6. การสร้างโมเดล 3 มิติ

กราฟิก 2 มิติอยู่บนระนาบเดียว ใช้พิกัด (x, y) ส่วนกราฟิก 3 มิติวางวัตถุได้ทุกที่ในอวกาศ จึงใช้พิกัด (x, y, z) โดย z บอกความลึก ว่าใกล้หรือไกลจากผู้มอง วัตถุ 3 มิติมีปริมาตร และผิวไม่จำเป็นต้องแบนราบ

วิธีสร้างวัตถุ 3 มิติ

วิธีที่ 1: รวม 3D primitives — primitives คือรูปทรง 3 มิติพื้นฐาน เช่น ทรงกลม ลูกบาศก์ ทรงกระบอก กรวย วงแหวนโดนัท นำมาจัดวางด้วย affine transform แล้วรวม ตัด หรือหาส่วนซ้อนด้วย Boolean operators

วิธีที่ 2: สร้างจากรูป 2 มิติ

  • Extrusion (การดึงยืด) — ดึงรูป 2 มิติออกไปในแกนที่สามให้มีความหนา เช่น ดึงรูปเฟืองแบน ๆ ให้เป็นเฟืองหนา หรือทำตัวอักษร 3 มิติ
  • Lathe หรือ Lathing (การกลึง) — หมุนเส้นโครงร่าง 2 มิติรอบแกน ได้วัตถุที่สมมาตรรอบแกน เช่น หมวก แก้ว แจกัน

Polygon mesh — วิธีเก็บผิวของวัตถุ 3 มิติ

ไม่ว่าจะสร้างวัตถุด้วยวิธีใด สุดท้ายผิวของมันมักถูกเก็บเป็น polygon (รูปหลายเหลี่ยมแบนราบ) จำนวนมากต่อกัน เรียกว่า polygon mesh เหมือนผิวหนังที่ประกอบจากเซลล์จำนวนมาก หน่วยที่เล็กที่สุดมักเป็นสามเหลี่ยมหรือสี่เหลี่ยม

องค์ประกอบของ polygon: Vertex (จุดยอด จุดที่เส้นขอบมาบรรจบ) · Edge (เส้นขอบที่เชื่อม vertex) · Face (พื้นผิวแบนที่ล้อมรอบด้วย edge)

ทำไมใช้ polygon mesh: (1) ยืดหยุ่น ประมาณรูปทรงได้แทบทุกแบบ (2) ละเอียด ยิ่งมี polygon มาก รูปยิ่งใกล้ของจริง เช่น ทรงกลมจาก 20 polygon ดูเป็นเหลี่ยม แต่จากหลายร้อย polygon ดูกลมเนียน (3) แก้ไขง่าย ปรับเฉพาะ polygon ที่เลือกได้ เช่น extrude หน้าเดียวให้ยื่นออกมา

Parametric surface (เช่น NURBS) สร้างผิวโค้งเรียบด้วยสมการ เหมาะกับตัวรถหรือเครื่องบิน แต่ก่อนเรนเดอร์ต้องแปลงเป็น polygon mesh เสมอ เหมือนที่เวกเตอร์ 2 มิติต้องแปลงเป็นบิตแมปก่อนแสดงผล

ขั้นสุดท้ายของการสร้างโมเดล

เมื่อได้รูปทรงแล้ว ต้องกำหนดว่าผิวของวัตถุ “ทำจากอะไร” เพื่อให้แสงตกกระทบแล้วดูสมจริง:

  • Material (วัสดุ) — กำหนดสีและความสว่างของผิว และค่าที่บอกว่าผิวสะท้อนแสงอย่างไร ค่าที่ใช้บ่อยมี 3 ตัว (ในสไลด์เป็นรูปลูกบอลที่ค่า 0, 0.5, 1):
    • Specular — ผิวมีจุดสะท้อนแสงจ้า (highlight) แรงแค่ไหน ค่า 0 ผิวด้านไม่มีจุดจ้า ค่า 1 มีจุดจ้าชัด
    • Roughness (ความหยาบ) — ผิวเรียบหรือหยาบในระดับเล็กมาก ผิวเรียบ (ค่าต่ำ) จุดจ้าเล็กและคมเหมือนกระจก ผิวหยาบ (ค่าสูง) แสงกระจาย จุดจ้าฟุ้งกว้างจนดูด้าน
    • Metallic (ความเป็นโลหะ) — ค่า 0 คือวัสดุทั่วไปอย่างพลาสติกหรือไม้ ค่า 1 คือโลหะ ซึ่งสะท้อนสภาพแวดล้อมรอบตัวเหมือนกระจก และแสงสะท้อนมีสีตามเนื้อโลหะ (เช่น ทองสะท้อนเป็นสีทอง)
  • Texture — แปะภาพ 2 มิติลงบนผิว เช่น ลายไม้ ลายหิน ทำให้มีรายละเอียดโดยไม่ต้องเพิ่ม polygon
  • การจำลองผิวพิเศษ — เช่น ทำให้ผิวดูขรุขระหรือมันเงา
  • การตอบสนองต่อแสงและตัวเลือกการเรนเดอร์ — เงา การสะท้อน การหักเหของแสง

7. การเรนเดอร์ภาพ 3 มิติ

3D rendering คือการแปลงโมเดล 3 มิติเป็นภาพ 2 มิติ ตามที่กล้องเสมือน (virtual camera)มองเห็น โดยจำลองสิ่งที่เกิดในโลกจริง 3 อย่าง: แหล่งกำเนิดแสงส่องอย่างไร · วัตถุแต่ละแบบทำปฏิกิริยากับแสงอย่างไร (สะท้อน หักเห กระเจิง) · และกล้องหรือตารับแสงที่สะท้อนมาอย่างไร

การสะท้อนแสง 2 แบบ

  • Specular reflection — เกิดบนผิวมันเรียบ เช่น โลหะขัดเงา แสงสะท้อนไปทิศเดียว มุมตกกระทบเท่ากับมุมสะท้อน จึงเห็นเป็นจุดสว่างจ้า (highlight)
  • Diffuse reflection — เกิดบนผิวหยาบ เช่น ไม้หรือผ้า แสงกระจายออกหลายทิศ ผิวจึงดูนุ่มนวล ไม่มีจุดจ้า

ปัจจัยที่กำหนดว่ากล้องรับแสงแบบไหน: ชนิด สี และความเข้มของแหล่งแสง · ชนิดผิวของวัตถุ · ตำแหน่งและมุมกล้อง · วัตถุอื่นที่บังแสงจนเกิดเงา · แสงที่สะท้อนมาจากวัตถุใกล้เคียง

3 ขั้นตอนของ real-time rendering (ช่วยจำ “Per–Vi–Shade”)

  1. Perspective projection — ฉาย polygon จาก 3 มิติลงบนระนาบ 2 มิติของกล้อง ทำให้ของใกล้ดูใหญ่ ของไกลดูเล็ก
  2. Visibility check — ตรวจว่าผิวไหนถูกบัง (เช่น ด้านหลังของลูกบอล) แล้วไม่ต้องวาด ช่วยประหยัดการคำนวณ
  3. Shading — คำนวณสีและความสว่างของแต่ละส่วน มี 3 วิธี:
    • Flat shading — ทั้ง polygon ใช้สีเดียว จึงเห็นเป็นเหลี่ยม ๆ
    • Gouraud shading — คำนวณสีที่ vertex แล้วไล่สีระหว่าง vertex รอยต่อจึงเนียนขึ้น
    • Phong shading — คำนวณแสงทุกพิกเซล ได้ผิวเนียนและ highlight สมจริงที่สุด

ภาพ wireframe 2 ภาพที่ต่างกันแค่ “เห็นเส้นด้านหลังหรือไม่” → visibility check · ทรงกลม 2 ลูกที่ต่างกันแค่ “เหลี่ยมหรือเนียน” → shading · จุดจ้าสีขาวบนลูกบอลมัน → specular reflection

CH7 · คอมพิวเตอร์แอนิเมชัน

แอนิเมชันคืออะไร มีกี่ประเภท คอมพิวเตอร์สร้างเฟรมระหว่างกลางอย่างไร ควบคุมความเร็วอย่างไร และเทคนิคขั้นสูงมีอะไรบ้าง

1. แอนิเมชันคืออะไร

คำว่า animate มาจากภาษาละติน animare แปลว่า “ทำให้มีชีวิต” แอนิเมชันจึงคือการทำให้ภาพวาดหรือวัตถุที่นิ่งอยู่ดูเหมือนมีชีวิต โดยแสดงภาพนิ่งหลายภาพต่อกันอย่างรวดเร็ว

สิ่งที่ทำให้เราเห็นภาพนิ่งเป็นการเคลื่อนไหวคือ persistence of vision (การคงอยู่ของภาพในการรับรู้) ภาพที่เพิ่งเห็นยังค้างอยู่ชั่วขณะ เมื่อภาพถัดไปมาเร็วพอ สมองจึงรวมภาพเป็นการเคลื่อนไหว

ตัวเลขสำคัญ 2 ตัวที่ต้องแยกให้ออก:

  • อัตราการฉาย ต้องอย่างน้อย 50 ภาพต่อวินาที (fps) จึงจะไม่เห็นภาพกะพริบ (flicker)
  • จำนวนภาพที่แตกต่างกันจริง แค่ประมาณ 12 ภาพต่อวินาทีก็ดูเคลื่อนไหวมีชีวิตแล้ว (ภาพเดียวกันถูกฉายซ้ำหลายครั้ง) ภาพยนตร์ทั่วไปใช้ 24 fps

“ต้องวาดภาพที่ต่างกันอย่างน้อย 12 frame ต่อวินาที เพื่อไม่ให้เกิด flicker” → ผิด เพราะ flicker แก้ด้วยอัตราการฉาย 50 fps ไม่ใช่จำนวนภาพที่วาด

2. ประเภทของแอนิเมชัน

2.1 Traditional hand-drawn animation (วาดมือแบบดั้งเดิม)

วาดภาพทีละเฟรมบนกระดาษ ผ้าใบ กระจก หรือแผ่นเซลลูลอยด์ใส (celluloid หรือ cel) แล้วถ่ายด้วยกล้องทีละเฟรม เป็นแอนิเมชันรูปแบบแรกที่ทำเป็นธุรกิจได้ แต่ต้นทุนสูงมาก เพราะต้องวาดหลายพันเฟรมเพื่อได้งานไม่กี่นาที

Walt Disney คิดค้น 2 อย่างเพื่อลดต้นทุนและเพิ่มความสมจริง:

  • Cel animation — วาดตัวละครบนแผ่นใส วาดฉากหลังแยกไว้แผ่นเดียว แล้ววางแผ่นตัวละครซ้อนบนฉากหลัง ไม่ต้องวาดฉากหลังซ้ำทุกเฟรม และนำแผ่น cel เดิมกลับมาใช้ซ้ำได้
  • Multiplane camera — กล้องที่ถ่ายผ่านแผ่น cel หลายชั้นซึ่งวางห่างจากกล้องต่างระยะ เมื่อกล้องเคลื่อน ชั้นที่อยู่ใกล้จะเลื่อนเร็วกว่าชั้นที่อยู่ไกล เกิด parallax effect ภาพจึงดูมีความลึกเหมือนผู้ชมเคลื่อนเข้าไปในฉาก

2.2 Computer-based hand-drawn animation (วาดมือด้วยคอมพิวเตอร์)

ใช้ซอฟต์แวร์แทนแผ่น cel และกล้อง multiplane (เช่น Toon Boom Harmony, Adobe Animate) ศิลปินวาดบนกระดาษแล้วสแกน หรือวาดในโปรแกรมด้วยเมาส์ปากกา ดูผลได้ทันที แก้ไขง่าย ประหยัดเวลา แต่ศิลปินยังต้องวาดทุกเฟรมเอง

2.3 Stop-motion animation

ถ่ายภาพนิ่งของวัตถุจริง เช่น หุ่นหรือโมเดลดินน้ำมัน ทีละเฟรม โดยขยับท่าทางหรือตำแหน่งทีละนิดระหว่างเฟรม เช่น Wallace and Gromit เคยใช้ทำเอฟเฟกต์ในหนังคนแสดง เช่น หุ่น AT-AT ใน Star Wars: The Empire Strikes Back (1980) แต่ปัจจุบันในหนังคนแสดงถูกแทนด้วย CGI เกือบหมด

2.4 2D computer animation

คอมพิวเตอร์ช่วยสร้างเฟรมบางส่วนให้อัตโนมัติ ศิลปินวาดเฉพาะ key frame (เฟรมหลักที่เป็นท่าสำคัญ เช่น ท่าเริ่มกระโดดกับท่าลอยสูงสุด) แล้วคอมพิวเตอร์สร้าง in-between frames (เฟรมระหว่างกลาง) ให้ เรียกว่า tweening (มาจาก in-betweening) ชื่อ key frame มาจากยุคดั้งเดิม ที่ศิลปินอาวุโสวาดเฟรมหลัก แล้วให้ศิลปินรุ่นน้องวาดเฟรมระหว่างกลาง

2.5 3D computer animation

วัตถุมีปริมาตร หมุนดูได้รอบด้าน ภาพสุดท้ายเกิดจากการจำลองแสง วัสดุผิว และกล้อง จำลองสิ่งที่ 2D ทำยากได้ เช่น น้ำไหล คลื่นทะเล เปลวไฟ และใช้พลังประมวลผลของ GPU มาก ขั้นตอนการผลิตซับซ้อนกว่า 2D:

  1. Modeling — สร้างรูปทรง 3 มิติของตัวละครและฉาก (polygon mesh ตาม CH6)
  2. Rigging — ใส่ “โครงกระดูก” (กระดูกและข้อต่อ) เข้าไปในโมเดล แล้วผูกผิวกับกระดูก เมื่อขยับกระดูก ผิวจะขยับตาม เหมือนหุ่นกระบอกที่มีเส้นเชือกให้ชัก
  3. Animation — กำหนดการเคลื่อนไหว ด้วย key frame, motion capture หรือการจำลองฟิสิกส์
  4. Texturing — ใส่สี วัสดุ และลวดลายบนผิว
  5. Lighting — วางแหล่งแสงในฉาก กำหนดชนิด สี และความแรงของแสง
  6. Rendering — ให้คอมพิวเตอร์คำนวณภาพออกมาทีละเฟรมตามขั้นตอนใน CH6

3. Interpolation function (ฟังก์ชันหาค่าระหว่างกลาง)

การ tween ต้องคำนวณว่าในแต่ละเฟรมระหว่างกลาง วัตถุควรอยู่ตรงไหน หน้าตาเป็นอย่างไร เครื่องมือที่ใช้คือ interpolation function ซึ่งรับค่าจาก key frame แล้วคำนวณค่าระหว่างกลางให้ ใช้คำนวณได้ทั้งตำแหน่ง รูปร่าง มุมการหมุน และสี

วัตถุเวกเตอร์ tween ได้โดยตรง เพราะเก็บเป็นตัวเลขอยู่แล้ว ส่วนภาพบิตแมปต้องทำผ่าน proxy object เช่น กรอบสี่เหลี่ยมที่ครอบภาพ แล้ว interpolate กรอบนั้นแทน

ฟังก์ชันที่นิยมคือ Bezier curve อีกแบบที่ใช้กันคือ Hermite curve ซึ่งต่างกันที่วิธีกำหนดเส้น:

  • Bezier กำหนดด้วยจุดควบคุม 4 จุด (สำหรับ cubic) จุดกลาง 2 จุดเป็นตัวดึงความโค้ง เส้นไม่ผ่านจุดเหล่านั้น
  • Hermite กำหนดด้วยข้อมูล 4 อย่าง คือ จุดเริ่ม P0 จุดจบ P1 และเวกเตอร์สัมผัส (tangent) T0 และ T1 ที่จุดเริ่มกับจุดจบ ซึ่งบอกว่าวัตถุควรออกตัวและเข้าเส้นชัยไปทางไหน ด้วยความเร็วเท่าไร เส้นผ่านทั้งจุดเริ่มและจุดจบเสมอ

Hermite เหมาะกับแอนิเมชัน เพราะ key frame บอกตำแหน่งเริ่มและจบอยู่แล้ว ผู้ทำแค่กำหนดทิศทางและความเร็วที่สองจุดนั้น ก็ได้การเคลื่อนไหวที่เรียบ (ทั้งสองแบบแปลงหากันได้ทางคณิตศาสตร์)

“ข้อใดเป็นบทบาทของ interpolation function” (รูปร่าง ตำแหน่ง การหมุน สี) → ถูกทุกข้อ — ข้อนี้คุณเคยตอบผิดในแบบฝึกหัด

4. Continuity — ความต่อเนื่องที่จุดต่อเส้นโค้ง

เมื่อต่อ Bezier หลายเส้นเป็น spline ต้องดูว่าที่จุดต่อนั้น “เรียบ” แค่ไหน โดยใช้อนุพันธ์ (derivative) ของเส้น ซึ่งอธิบายง่าย ๆ ได้ว่า

  • อนุพันธ์อันดับ 1 (1st derivative) = ทิศทางและความเร็วของการเคลื่อนที่ ณ จุดนั้น (เส้นสัมผัส หรือ velocity)
  • อนุพันธ์อันดับ 2 (2nd derivative) = การเปลี่ยนแปลงของความเร็วและทิศทาง (ความเร่ง หรือความโค้ง)

ความต่อเนื่องมี 2 ตระกูล:

  • G (geometric continuity) สนใจแค่ทิศทาง ว่าเส้นดูเรียบด้วยตาหรือไม่
  • C (parametric continuity) สนใจทั้งทิศทางและขนาด จึงเรียบทั้งด้วยตาและเรียบในการเคลื่อนที่จริง เหมาะกับแอนิเมชัน
ระดับเงื่อนไขภาพในหัว
G0 = C0จุดปลายของเส้นแรกตรงกับจุดเริ่มของเส้นถัดไปเส้นแตะกันพอดี แต่อาจหักเป็นมุม
G1ทิศทางของเส้นสัมผัสตรงกัน (ไม่สนขนาด)ไม่มีมุมหัก แต่ความเร็วอาจกระตุกที่จุดต่อ
C1เส้นสัมผัสเท่ากันทั้งทิศทางและขนาดเรียบและความเร็วต่อเนื่อง
G2ทิศทางของอนุพันธ์อันดับ 2 ตรงกันความโค้งต่อเนื่อง
C2อนุพันธ์อันดับ 2 เท่ากันทั้งทิศและขนาดความเร่งต่อเนื่อง เรียบที่สุด

กฎที่ต้องจำ: Cx ทำให้ได้ Gx เสมอ (C เข้มงวดกว่า) และระดับสูงรวมระดับต่ำไว้ด้วย เช่น มี G2 ก็ต้องมี G1 และ G0

นึกถึงรถที่ขับผ่านจุดต่อของถนน 2 ช่วง: G1 คือถนนต่อกันโดยไม่หักมุม แต่ป้ายจำกัดความเร็วเปลี่ยนทันทีที่จุดต่อ รถจึงต้องเร่งหรือเบรกกะทันหัน ส่วน C1 คือทั้งทิศทางและความเร็วต่อเนื่อง รถวิ่งผ่านไปได้ลื่น ๆ

“G1 ไม่แตกต่างจาก C1” → ผิด · ข้อใดไม่เกี่ยวกับการตรวจ G2 → ขนาด (magnitude) ของ 1st derivative เพราะ G ไม่สนขนาด · ข้อใดไม่เกี่ยวกับการตรวจ C2 (C0, C1, 1st, 2nd derivative) → ทุกข้อเกี่ยวข้องหมด

5. แอนิเมชันที่อาศัย interpolation

interpolation function ใช้ทำ 3 อย่าง: กำหนดเส้นทางการเคลื่อนที่ (motion path) · ควบคุมความเร็ว (speed control) · และกำหนดการเปลี่ยนรูปร่างตามเวลา

การควบคุมความเร็วด้วย curve แยก

ปัญหาคือ ค่าพารามิเตอร์ u ของ curve ไม่ได้สัมพันธ์กับระยะทางแบบเท่ากัน ถ้าเพิ่ม u ทีละเท่า ๆ กัน วัตถุอาจวิ่งเร็วบ้างช้าบ้างโดยไม่ตั้งใจ จึงต้องแยก “ระยะทาง” ออกมาควบคุมเอง ทำ 4 ขั้น:

  1. Normalize ระยะทาง ให้ระยะทางทั้งหมดบนเส้นทางอยู่ระหว่าง 0 ถึง 1 (ใช้ตัวแปร s)
  2. Speed control curve S(t) รับเวลา t แล้วบอกว่าเวลานั้นวัตถุควรไปถึงระยะทาง s เท่าไร เช่น S(t) = (2 − t)·t ให้ S(0) = 0, S(0.5) = 0.75, S(1) = 1 แปลว่าครึ่งเวลาแรกไปได้ถึง 75% ของทาง คือออกตัวเร็วแล้วค่อย ๆ ช้าลง
  3. Arc length table แปลงระยะทาง s เป็นพารามิเตอร์ u = U(s)
  4. แทน u ใน curve ได้ตำแหน่งจริง p = P(U(S(t)))

โจทย์จากแบบฝึกหัด: ตาราง arc length มี v = 0.15 → 0.230, v = 0.20 → 0.320, v = 0.25 → 0.400 ถ้า S(t₀) = 0.32 แปลว่า ณ เวลา t₀ ต้องไปถึงระยะทาง 0.32 เปิดตารางหาระยะทาง 0.320 ตรงกับ v = 0.20 ตำแหน่งจึงเป็น P(0.2) — ไม่ใช่ P(0.32) เพราะ 0.32 คือระยะทาง ไม่ใช่พารามิเตอร์ (ข้อนี้คุณเคยตอบผิด)

Motion animation (motion tween)

สร้าง in-between frames ของตำแหน่ง ขนาด และการหมุน จาก key frame แรกถึง key frame สุดท้าย หลักการที่เกี่ยวข้องคือ slow in and slow out เพราะของจริงไม่ได้เริ่มหรือหยุดทันที:

  • Ease-in — เริ่มช้า แล้วค่อย ๆ เร็วขึ้น (เหมือนรถออกตัว)
  • Ease-out — วิ่งมาเร็ว แล้วค่อย ๆ ช้าลงจนหยุด (เหมือนรถเบรกเข้าจอด)

Shape animation (shape tween)

เปลี่ยนคุณสมบัติของวัตถุจาก key frame แรกไปสุดท้าย เช่น รูปทรง สี ความโปร่งใส ลวดลาย หลักการที่เกี่ยวข้องคือ squash and stretch: เมื่อลูกบอลกระแทกพื้นจะถูกบีบแบน (squash) เมื่อพุ่งขึ้นจะยืดยาว (stretch) โดยปริมาตรคงที่ ยืดสูงขึ้นก็ต้องผอมลง ทำให้ดูมีน้ำหนักและมีชีวิต

Morphing animation

การเปลี่ยนภาพ 2 มิติจากภาพต้นทางเป็นภาพปลายทางอย่างลื่นไหล เช่น ใบหน้าคน A ค่อย ๆ กลายเป็นคน B ใช้เวกเตอร์เป็นตัวกลาง (proxy) ด้วยเทคนิค Free Form Deformation (FFD) ซึ่งวางตารางจุดควบคุมบนภาพ ขยับจุดแล้วภาพบิดตาม มี 3 ขั้น:

  1. Point mapping — วางตาราง (grid) บนภาพทั้งสอง และจับคู่จุดสำคัญ เช่น ตาคู่กับตา ปากคู่กับปาก
  2. Image warping — interpolate ตารางตามเวลา แล้วบิดภาพทั้งสองให้รูปร่างตรงกับตารางกลาง
  3. Cross-dissolving — ผสมสีของภาพทั้งสอง โดยค่อย ๆ ลดภาพแรกและเพิ่มภาพหลัง

6. เทคนิคขั้นสูง

Human figure animation

ใช้ hierarchical modeling จัดชิ้นส่วนร่างกายเป็นลำดับชั้นแม่-ลูก (parent-child) เช่น ไหล่ → แขน → ข้อศอก → มือ ชิ้นลูกสืบทอดการเคลื่อนไหวจากชิ้นแม่ หมุนไหล่แล้วแขนและมือหมุนตามเอง ควบคุมได้ 2 แบบ:

  • Forward kinematics (FK) — เริ่มจากราก (root) แล้วคำนวณตำแหน่งลูกตามไป เช่น หมุนไหล่ แขนและมือตาม
  • Inverse kinematics (IK) — เริ่มจากปลาย (leaf) กำหนดตำแหน่งที่ปลายต้องไปถึง แล้วคำนวณย้อนว่าข้อต่อด้านบนต้องเป็นมุมเท่าไร เช่น กำหนดให้มือจับแก้ว ระบบหามุมข้อศอกและไหล่เอง

Physically-based animation

ใช้แบบจำลองทางฟิสิกส์ (แรง มวล แรงโน้มถ่วง การชน การไหล) คำนวณการเคลื่อนไหว แทนการกำหนดด้วยมือ เหมาะกับการเคลื่อนไหวที่ซับซ้อนเกินจะวาดเอง หรือแอปที่ต้องตอบสนองแบบ real-time เช่น เกม ตัวอย่าง: ใบไม้ไหวตามลม น้ำไหล คลื่นทะเล เปลวไฟ ฝูงนก

Facial animation และ motion capture

Facial animation คือการทำให้ใบหน้าตัวละครแสดงอารมณ์และขยับปากตามคำพูด ซึ่งยากเพราะคนดูไวต่อหน้าคนมาก ผิดนิดเดียวก็ดูแปลก วิธีที่ใช้ เช่น:

  • Key frame — ศิลปินปั้นท่าหน้าหลัก เช่น ยิ้ม ขมวดคิ้ว แล้วให้คอมพิวเตอร์สร้างเฟรมระหว่างกลาง
  • Blend shapes (morph targets) — ปั้นหน้าไว้หลายแบบ เช่น ปากยิ้ม ปากออกเสียง “อา” ตาหลับ แล้วผสมกันในสัดส่วนต่าง ๆ เพื่อได้สีหน้าที่ซับซ้อน

Motion capture (mocap) คือการบันทึกการเคลื่อนไหวจากคนจริง: นักแสดงใส่ชุดที่ติดลูกบอลสะท้อนแสงเล็ก ๆ (marker) ตามข้อต่อ กล้องหลายตัวรอบห้องถ่ายพร้อมกัน คอมพิวเตอร์คำนวณตำแหน่ง 3 มิติของ marker แต่ละจุดในทุกเฟรม แล้วนำไปขับโครงกระดูกของตัวละคร ได้การเคลื่อนไหวสมจริงโดยไม่ต้องทำ key frame ทุกเฟรม ใช้กับใบหน้าได้ด้วย (facial motion capture) ตัวอย่างคือ Gollum ใน The Lord of the Rings และตัวละครใน Avatar

CH8 · เสียง (Sound)

เสียงคืออะไร บันทึกเป็นดิจิทัลอย่างไร ปรับแต่งอย่างไร บีบอัดอย่างไร สังเคราะห์อย่างไร และทำให้ได้ยินเป็นมิติได้อย่างไร

1. พื้นฐานของเสียง

Sound (เสียง) คือการสั่นสะเทือนที่เดินทางเป็นคลื่นผ่านตัวกลาง เช่น อากาศ น้ำ หรือของแข็ง ส่วน audio คือเสียงที่ถูกแปลงเป็นสัญญาณไฟฟ้าเพื่อเก็บหรือประมวลผล ซึ่งมีทั้งแบบแอนะล็อก (สัญญาณต่อเนื่อง เช่น แผ่นเสียง เทปคาสเซ็ต) และแบบดิจิทัล (ตัวเลข เช่น ซีดี MP3) หูมนุษย์ได้ยินเสียงในช่วงความถี่ 20 Hz ถึง 20,000 Hz

คุณสมบัติของเสียง

  • Amplitude (แอมพลิจูด) — ความแรงของการบีบและคลายของอากาศ ยิ่งมากเสียงยิ่งดังเพราะพลังงานมาก และจะลดลงเมื่อเสียงเดินทางไกลขึ้น
  • Frequency (ความถี่) — จำนวนรอบการบีบคลายต่อวินาที หน่วยเฮิรตซ์ (Hz) ความถี่สูงเป็นเสียงแหลม ความถี่ต่ำเป็นเสียงทุ้ม
  • Wavelength (ความยาวคลื่น) — ระยะระหว่างยอดคลื่นที่ติดกัน สัมพันธ์กับความถี่ด้วยสูตร ความเร็วเสียง = ความถี่ × ความยาวคลื่น ความถี่สูงความยาวคลื่นจึงสั้น
  • Spectrum (สเปกตรัม) — เสียงจริงไม่ได้มีความถี่เดียว แต่ประกอบด้วยหลายความถี่รวมกัน spectrum คือกราฟที่บอกว่าแต่ละความถี่ดังเท่าไร เครื่องดนตรีต่างชนิดมี spectrum ต่างกัน เราจึงแยกเสียงไวโอลินกับแซกโซโฟนได้แม้เล่นโน้ตเดียวกัน ดังเท่ากัน
  • Loudness (ความดัง) — การรับรู้ความแรงของเสียงของหู วัดเป็นเดซิเบล (dB)

แนวคิดเบื้องหลัง spectrum คือ Fourier: สัญญาณใด ๆ สร้างได้จากคลื่น sine หลายความถี่รวมกัน และ Fourier transform คือการแยกสัญญาณออกเป็นความถี่ย่อยเหล่านั้น

“ข้อใดไม่ใช่คุณสมบัติของ sound” → Digital or Analog (เป็นรูปแบบของ audio ไม่ใช่คุณสมบัติของเสียง)

เดซิเบล (decibel)

สูตร dB = 10 × log(I / I₀) โดย I คือความเข้มเสียง และ I₀ = 10⁻¹² W/m² คือความเข้มต่ำสุดที่หูเริ่มได้ยิน สเกลนี้เป็น log จึงเพิ่มแบบทวีคูณ: ทุก ๆ +10 dB พลังงานเพิ่ม 10 เท่า แต่หูรับรู้ว่าดังขึ้นประมาณ 2 เท่า เช่น ถนนในเมือง 85 dB กับคอนเสิร์ตร็อก 105 dB ต่างกัน 20 dB พลังงานต่างกัน 10 × 10 = 100 เท่า เสียงดิจิทัลใช้หน่วย dBFS (decibels relative to full scale) ซึ่งค่าสูงสุดที่บันทึกได้คือ 0 dBFS

2. การบันทึกเสียงเป็นดิจิทัล

ไมโครโฟนมีแผ่นบาง (diaphragm) ที่สั่นตามแรงดันอากาศ แล้วแปลงเป็นสัญญาณไฟฟ้าที่มีรูปคลื่นเหมือนเสียงจริง (analog audio) สัญญาณถูกขยายด้วย gain แล้วส่งเข้า ADC (analog-to-digital converter) เพื่อแปลงเป็นตัวเลข เก็บในคอมพิวเตอร์ ตอนเล่นกลับใช้ DAC (digital-to-analog converter) แปลงกลับเป็นสัญญาณไฟฟ้าส่งไปลำโพง

เสียง→ไมโครโฟน→ขยายด้วย gain→ADC→คอมพิวเตอร์→DAC→ลำโพง

Dynamic range และ clipping

Dynamic range คือช่วงระหว่างเสียงที่ดังที่สุดกับเสียงที่เบาที่สุด (ที่ยังได้ยิน) ในการบันทึก

Clipping เกิดเมื่อสัญญาณดังเกินระดับสูงสุดที่ ADC รับได้ (เกิน 0 dBFS) ยอดคลื่นจะถูกตัดแบน เสียงแตกพร่า (distortion) และแก้ภายหลังไม่ได้ วิธีป้องกันคือตั้ง analog gain ที่ไมโครโฟนหรือ preamp ให้เหมาะสมตั้งแต่ตอนบันทึก

  • Preamp (pre-amplifier) — วงจรขยายสัญญาณที่อยู่ก่อน ADC (มักอยู่ใน audio interface) สัญญาณจากไมโครโฟนเบามาก จึงต้องขยายให้แรงพอก่อนแปลงเป็นดิจิทัล ปุ่ม gain คือปุ่มปรับว่าจะขยายมากแค่ไหน
  • Gain ต่ำไป — เสียงเบาเกิน ใช้ช่วงของ ADC ไม่เต็ม เมื่อนำมาเร่งทีหลัง noise ก็ถูกเร่งตามไปด้วย
  • Gain สูงไป — ช่วงที่ดังที่สุดเกิน 0 dBFS เกิด clipping
  • Headroom — “ที่ว่างเผื่อ” ระหว่างระดับเสียงปกติกับเพดาน 0 dBFS เช่น ตั้งให้เสียงดังสุดอยู่ราว −6 dBFS ถ้ามีเสียงพุ่งขึ้นกะทันหัน (ตะโกน ตีกลอง) ก็ยังไม่ชนเพดาน

Sampling rate และ bit depth

Sampling rate คือจำนวนครั้งที่วัดค่าสัญญาณต่อวินาที เช่น ซีดีใช้ 44,100 ครั้งต่อวินาที (44.1 kHz) ยิ่งสูงยิ่งเก็บความถี่สูงได้ (ความรู้เสริมนอกสไลด์: ตามทฤษฎี Nyquist เก็บได้ถึงประมาณครึ่งหนึ่งของ sampling rate)

Bit depth คือจำนวนบิตที่ใช้เก็บค่าความแรงของแต่ละ sample เช่น 16 บิตแทนได้ 65,536 ระดับ การปัดค่าจริงให้ลงระดับที่ใกล้ที่สุดเรียกว่า quantization ความต่างระหว่างค่าจริงกับค่าที่ปัดเรียกว่า quantization noise (เฉลี่ยครึ่งระดับ)

คุณภาพวัดด้วย SQNR ≈ 6.02N + 1.76 dB (signal-to-quantization-noise ratio) โดย N คือจำนวนบิต แปลว่าทุก 1 บิตที่เพิ่ม ลด noise ได้ประมาณ 6 dB

N = 10 → 6.02 × 10 + 1.76 = 61.96 ≈ 60 dB (ออกสอบ) · N = 16 → 98 dB · N = 24 → 146 dB

Dithering คือการเติม noise เล็กน้อยแบบสุ่มก่อน quantize โดยเฉพาะตอนลด bit depth เช่น จาก 24 เป็น 16 บิต ทำให้ความผิดพลาดกลายเป็น noise เรียบ ๆ ที่ฟังเป็นธรรมชาติ แทนที่จะเป็นเสียงกระด้างผิดเพี้ยน

3. การประมวลผลเสียง

Filter (ตัวกรอง) — ตัดหรือคัดเลือกช่วงความถี่

ชนิดทำอะไรตัวอย่างการใช้
Low-passให้ความถี่ต่ำกว่าเกณฑ์ผ่าน ตัดความถี่สูงทิ้งลดเสียงซ่า ทำเสียงนุ่มลง
High-passให้ความถี่สูงกว่าเกณฑ์ผ่าน ตัดความถี่ต่ำทิ้งตัดเสียงลม เสียงฮัมความถี่ต่ำ
Band-passให้ผ่านเฉพาะช่วงความถี่ที่กำหนดเลือกเฉพาะย่านเสียงพูด
Band-stop (notch)ตัดทิ้งเฉพาะช่วงความถี่ที่กำหนด ที่เหลือผ่านหมดตัดเสียงไฟฟ้า 50 Hz หรือเสียงพัดลม 600 Hz

เสียงมอเตอร์พัดลม 600 Hz แทรกในเสียงพูด → band-stop filter เพราะ 600 Hz อยู่กลางย่านเสียงพูด ถ้าใช้ low-pass หรือ high-pass จะเสียเสียงพูดไปครึ่งหนึ่ง

Equalizer (EQ) — ปรับสมดุล

EQ ไม่ได้ตัดทิ้ง แต่เพิ่มหรือลดความดังของแต่ละย่านความถี่ให้เสียงสมดุล · Graphic EQ มีแถบความถี่ตายตัวหลายแถบ เลื่อนขึ้นลงได้ (เช่น EQ 10 แถบในเครื่องเสียงรถ) · Parametric EQ ไม่มีแถบตายตัว ปรับเองได้ทั้งความถี่ ระดับ และความกว้างของช่วง ใช้ในสตูดิโอ

Reverb (เสียงก้อง)

ในโลกจริงเราได้ยินทั้งเสียงตรงและเสียงสะท้อนจากผนัง พื้น เพดาน จึงรับรู้ได้ว่าอยู่ในสถานที่แบบไหน ใช้สร้างบรรยากาศของสถานที่ (soundscape) ไมโครโฟนที่อยู่ใกล้ปากจะได้เสียงตรงเกือบล้วน จึงต้องเติม reverb ให้ฟังเป็นธรรมชาติ องค์ประกอบเรียงตามเวลา:

  1. Direct sound (dry) — เสียงตรงที่ไม่ผ่านการสะท้อน มาถึงก่อนและดังที่สุด บอกทิศทางของแหล่งเสียง
  2. Early reflections — เสียงสะท้อนชุดแรกจากพื้นผิวใกล้ ๆ มาถึงหลังเสียงตรง 10–50 มิลลิวินาที ช่วงเวลาที่รอเสียงสะท้อนแรกบอกขนาดห้อง และมีผลต่อความชัดและความดัง
  3. Late reverberant sound (reverb tail) — มาหลัง 50 มิลลิวินาที เป็นเสียงที่สะท้อนไปมาหลายพื้นผิวหลายครั้งจนผสมเป็นเนื้อเดียว มาจากทุกทิศ จึงซับซ้อนที่สุด

ถ้าเสียงสะท้อนมาช้ามากจนแยกได้ยินเป็นเสียงซ้ำ จะเรียกว่า echo

Vocoder (voice + encoder)

เดิมใช้บีบอัดเสียงพูดให้ bitrate ต่ำมาก (คุณภาพต่ำจึงไม่ค่อยใช้สื่อสารแล้ว) ปัจจุบันใช้สร้างเสียงสังเคราะห์ โดยมองว่าเสียงพูดเกิดจาก 2 ส่วน คือเสียงจากเส้นเสียง และการกรองโดยช่องทางเดินเสียง (ปาก ลิ้น ฟัน) vocoder จึงใช้ 2 สัญญาณ:

  • Carrier — เสียงสังเคราะห์ เช่น คลื่น sawtooth จากคีย์บอร์ด ทำหน้าที่แทนเส้นเสียง
  • Modulator — เสียงพูดหรือร้องของคน ใช้สกัดลักษณะการกรองของช่องทางเดินเสียง แล้วนำไปกรอง carrier

ผลคือเสียงเครื่องดนตรีที่พูดหรือร้องได้ เช่น เสียงหุ่นยนต์ในเพลง EDM

Auto-tune

ปรับเสียงร้องให้ตรงโน้ตแบบ real-time ใน 3 ขั้น: ตรวจจับความสูงของเสียง (pitch) → เปรียบเทียบกับโน้ตที่ใกล้ที่สุดในคีย์ที่ตั้งไว้ → แก้โดยเลื่อน pitch ไปที่โน้ตนั้น ค่าที่ตั้ง: คีย์ของเพลง และความเร็วในการดึงเสียง (retune speed) ถ้าดึงช้าเสียงยังเป็นธรรมชาติ ถ้าดึงทันทีจะได้เสียงหุ่นยนต์แบบ “hard-tune”

4. การบีบอัดเสียง

Lossless compression — บีบอัดแบบไม่สูญเสีย

คลายกลับมาได้เหมือนต้นฉบับ 100% แนวคิดคือ sample ที่อยู่ติดกันมีค่าใกล้กัน จึงทำนายค่าถัดไปจากค่าก่อนหน้า แล้วเก็บแค่ผลต่างระหว่างค่าจริงกับค่าที่ทำนาย ซึ่งเป็นตัวเลขเล็กจึงใช้บิตน้อยกว่า วิธีนี้เรียกว่า DPCM (differential pulse code modulation)

ค่าจริง 100, 102, 103, 101 ถ้าทำนายว่าเท่ากับค่าก่อนหน้า ผลต่างคือ 100, +2, +1, −2 ตัวเลขหลังจากตัวแรกเล็กมาก ใช้บิตน้อยลง และบวกกลับได้ค่าเดิมครบ

ตัวอย่าง: FLAC, ALAC (Apple), Dolby TrueHD (Blu-ray) ขนาดไฟล์เหลือประมาณ 40–60% ของต้นฉบับ

Lossy compression — บีบอัดแบบสูญเสีย

อาศัย psychoacoustics (ธรรมชาติการได้ยินของมนุษย์) ทิ้งเสียงที่หูไม่ได้ยินอยู่แล้ว กู้คืนไม่ได้แต่ไฟล์เล็กมาก ประมาณ 10:1 หลักการที่ใช้:

  • Threshold of hearing — ระดับเสียงต่ำสุดที่หูได้ยินในแต่ละความถี่ หูไวต่อแต่ละความถี่ไม่เท่ากัน (ไวสุดราว 2–5 kHz) เสียงที่เบากว่าเส้นนี้ไม่ต้องเก็บ
  • Frequency masking — เสียงดังที่ความถี่หนึ่ง (masker) ทำให้ไม่ได้ยินเสียงเบาที่ความถี่ใกล้เคียงซึ่งดังพร้อมกัน (maskee) เพราะเสียงดังยกเส้น threshold รอบตัวมันขึ้น เหมือนกระซิบในคอนเสิร์ตแล้วไม่มีใครได้ยิน
  • Temporal masking — เสียงดังบังเสียงเบาที่เกิดในช่วงเวลาใกล้กัน ทั้งก่อนหน้าเล็กน้อย (pre-masking สั้น) และหลังจากนั้น (post-masking นานกว่า) เหมือนฟ้าผ่าที่กลบเสียงฝนเบา ๆ

ก่อนดูขั้นตอน ต้องรู้จักคำว่า masking threshold: เส้น threshold of hearing ปกติบอกว่าเสียงต้องดังเท่าไรจึงจะได้ยิน เมื่อมีเสียงดัง (masker) เกิดขึ้น เส้นนี้จะถูกยกสูงขึ้นในย่านความถี่และช่วงเวลารอบ ๆ masker เส้นที่ถูกยกขึ้นนี้เรียกว่า masking threshold อะไรที่เบากว่าเส้นนี้ หูจะไม่ได้ยิน

ขั้นตอนแบบ MP3 มี 4 ขั้น:

  1. แยกความถี่ — ส่งเสียงผ่าน filter bank ซึ่งก็คือ band-pass filter 32 ตัวเรียงกัน แต่ละตัวปล่อยผ่านเฉพาะย่านความถี่ของตัวเอง ได้สัญญาณ 32 ย่าน (sub-band) ตั้งแต่เสียงทุ้มถึงเสียงแหลม ทำให้รู้ว่าย่านไหนมีเสียงดัง ย่านไหนมีเสียงเบา และจัดสรรบิตแยกเป็นรายย่านได้
  2. จัดกลุ่ม 12 samples — ในแต่ละย่าน รวม sample ที่ติดกัน 12 ตัวเป็นหนึ่งกลุ่ม หนึ่งเฟรมจึงมี 32 × 12 = 384 samples (ประมาณ 8.7 มิลลิวินาทีเมื่อสุ่มที่ 44.1 kHz) กลุ่มนี้เป็นหน้าต่างเวลาสั้น ๆ ที่ใช้ดูว่าภายในช่วงนั้นเสียงดังเกิดตอนไหน (ใช้กับ temporal masking) และใช้หา scale factor ของกลุ่ม คือค่าระดับสัญญาณสูงสุดในกลุ่ม ใช้ย่อหรือขยายตัวเลขทั้งกลุ่มให้อยู่ในช่วงมาตรฐานก่อน quantize (เหมือนบอกว่า “ทั้งกลุ่มนี้คูณด้วยค่านี้”) บิตที่มีจำกัดจึงถูกใช้กับรายละเอียดของสัญญาณเท่านั้น
  3. จัดสรรบิต (bit allocation) — psychoacoustic model คำนวณ masking threshold ของแต่ละย่าน จากนั้น ย่านที่สัญญาณเบากว่า masking threshold ได้ 0 บิต (ไม่เก็บเลย) · ย่านที่ได้ยิน ใช้บิตน้อยที่สุดที่ทำให้ quantization noise ยังต่ำกว่า masking threshold เพราะ noise นั้นจะถูกเสียงดังบังจนไม่ได้ยิน · ถ้า noise ยังดังเกินเส้นจึงเพิ่มบิต
  4. บันทึก — สำหรับแต่ละย่านเก็บ 3 อย่าง: จำนวนบิตที่ใช้ (ให้ตัวถอดรหัสรู้ว่าต้องอ่านกี่บิต) scale factor และข้อมูลที่ quantize แล้ว

ทำไมการยกเส้น threshold จึงประหยัดบิต: ทุก 1 บิตลด quantization noise ได้ราว 6 dB ถ้าในย่านหนึ่ง masker ทำให้ masking threshold สูงขึ้น 18 dB เราก็ยอมให้ noise ดังขึ้นได้ 18 dB โดยไม่มีใครได้ยิน แปลว่าใช้บิตน้อยลงได้ประมาณ 18 ÷ 6 = 3 บิตต่อ sample ในย่านนั้น

Codec ที่นิยม: MP3 · AAC (มาตรฐานมือถือ Apple Music และ YouTube คุณภาพดีกว่า MP3 ที่ขนาดเท่ากัน) · Vorbis (open source) — ระวัง codec ไม่ใช่ format ไฟล์ เช่น AAC มักเก็บในไฟล์ .m4a และ Vorbis เก็บในไฟล์ .ogg

DPCM, Dolby TrueHD, ALAC, FLAC, MP3 ข้อใดไม่เข้าพวก → MP3 (lossy) · “ข้อใดไม่เกี่ยวกับ lossy” (threshold, band-pass filter, temporal masking, frequency masking) → ทุกข้อเกี่ยวข้องหมด · เสียงความถี่ใกล้เคียงดังขึ้นแล้วอีกเสียงหายไป → frequency masking

5. การสังเคราะห์เสียง (sound synthesis)

คำพื้นฐานที่ต้องรู้ก่อน:

  • Oscillator — ตัวสร้างคลื่นเสียงที่ความถี่หนึ่งซ้ำไปเรื่อย ๆ เป็นแหล่งเสียงต้นทางของ synthesizer
  • รูปคลื่นพื้นฐาน — sine (โค้งเรียบ มีความถี่เดียว เสียงใสบริสุทธิ์) · square (สี่เหลี่ยม) · triangle (สามเหลี่ยม) · sawtooth (ฟันเลื่อย) สามแบบหลังมีความถี่ย่อย (harmonics) ผสมอยู่มาก เสียงจึงหนา เหมาะเป็นวัตถุดิบให้ filter ตัดแต่ง
  • LFO (low-frequency oscillator) — oscillator ความถี่ต่ำมากจนหูไม่ได้ยินเป็นเสียง ไม่ได้ใช้เป็นเสียงเอง แต่ใช้ “ขยับ” ค่าอื่นไปมาช้า ๆ เช่น ทำให้เสียงสั่นหรือสีเสียงเปลี่ยนเป็นจังหวะ

6. Stereo audio กับ 3D audio

Sound localization คือความสามารถของหูและสมองในการบอกว่าเสียงมาจากทิศไหน ใช้ 2 กลไก:

  • Cue (a) ความต่างระหว่างหูซ้ายกับขวา — เสียงจากด้านซ้ายถึงหูซ้ายก่อน (interaural time difference) และดังกว่าในหูซ้ายเพราะศีรษะบังหูขวา (interaural level difference) ใช้บอกซ้ายหรือขวา
  • Cue (b) การกรองเสียงโดยใบหู — เสียงจากหน้า หลัง บน ล่าง กระทบรอยหยักของใบหูต่างกัน ความถี่บางส่วนจึงถูกกรองต่างกัน สมองจำรูปแบบนี้ได้ จึงบอกทิศขึ้นลงและหน้าหลังได้

2. การเข้ารหัสตัวอักษร (character encoding)

คอมพิวเตอร์เก็บได้แค่ตัวเลข จึงต้องกำหนดว่าตัวอักษรแต่ละตัวแทนด้วยเลขอะไร การกำหนดนี้เรียกว่า character encoding ทำให้เก็บ ส่ง และประมวลผลข้อความได้

ASCII

ASCII (American Standard Code for Information Interchange) เป็นมาตรฐานแรกที่ใช้แพร่หลายบนคอมพิวเตอร์ส่วนบุคคล (ก่อนหน้านั้นมี EBCDIC บนเครื่อง IBM) ใช้ 7 บิต แทนได้ 128 ตัว (เลข 0 ถึง 127) ครอบคลุมตัวอักษรอังกฤษ ตัวเลข และสัญลักษณ์ เช่น A = 65, a = 97

Extended ASCII และ code page

หนึ่งไบต์มี 8 บิต แต่ ASCII ใช้แค่ 7 บิต จึงเหลือเลข 128 ถึง 255 ว่างอยู่ จึงนำไปใช้แทนตัวอักษรภาษาอื่น เรียกว่า extended ASCII แต่ละภาษาใช้ตารางต่างกัน ตารางเหล่านี้เรียกว่า code page เช่น ภาษาไทยใช้ windows-874 โปรแกรมต้องรู้ว่าไฟล์ใช้ code page ไหนจึงจะแสดงถูก ปัญหาของ extended ASCII:

  1. ถ้าเปิดด้วย code page ผิด จะเห็นตัวอักษรขยะ เช่น “ÔÇµÇ¢!!” แทนภาษาไทย
  2. มีที่ว่างแค่ 128 ตัว ไม่พอสำหรับภาษาจีน ญี่ปุ่น เกาหลี ที่มีตัวอักษรหลายพันตัว
  3. ไฟล์เดียวใส่หลายภาษาพร้อมกันได้ยาก เพราะใช้ code page ได้ทีละอัน

Unicode

Unicode เป็นมาตรฐานสากลที่แก้ปัญหาทั้งหมดข้างต้น: ไม่ต้องใช้ code page ทุกตัวอักษรของทุกภาษามีเลขไม่ซ้ำกัน ใส่หลายภาษาในไฟล์เดียวได้ และรองรับสัญลักษณ์พิเศษและ emoji Unicode แยกการทำงานเป็น 3 ชั้น:

  1. Coded character set — กำหนดเลขไม่ซ้ำให้ทุกตัวอักษร เลขนี้เรียกว่า code point เขียนเป็นเลขฐานสิบหกนำหน้าด้วย U+ เช่น A = U+0041, ก = U+0E01
  2. Code units — แปลง code point เป็นหน่วยขนาดคงที่ ขนาดขึ้นกับรูปแบบ เช่น 8, 16 หรือ 32 บิต
  3. Octets (bytes) — แปลง code unit เป็นลำดับไบต์สำหรับเก็บหรือส่ง

ตามตัว ก ผ่านทั้ง 3 ชั้น: (1) Unicode กำหนดให้ ก มี code point คือ U+0E01 (เลข 3585 ในฐานสิบ) เลขนี้เป็นแค่ “หมายเลขประจำตัว” ยังไม่ใช่ไบต์ที่เก็บในไฟล์ (2) ถ้าเลือก UTF-8 เลขนี้จะถูกแปลงเป็น code unit ขนาด 8 บิต 3 หน่วย คือ E0, B8, 81 ถ้าเลือก UTF-16 จะได้ code unit ขนาด 16 บิต 1 หน่วย คือ 0E01 (3) code unit ถูกเขียนลงไฟล์เป็นไบต์ ซึ่ง UTF-16 ต้องเลือกลำดับไบต์ด้วย คือ 0E 01 (big endian) หรือ 01 0E (little endian)

Code point ถูกจัดเป็นกลุ่มเรียกว่า plane มีทั้งหมด 17 plane แต่ละ plane มี 65,536 ตัว (2¹⁶) Plane 0 เรียกว่า BMP (Basic Multilingual Plane) สำคัญที่สุดเพราะมีตัวอักษรของภาษาส่วนใหญ่รวมถึงภาษาไทย

UTF-3232 บิตทุกตัวใช้ 32 บิตเท่ากัน เข้าถึงง่ายแต่เปลืองที่

ลำดับไบต์ (byte order) — ข้อมูลที่ยาวกว่า 1 ไบต์ต้องเลือกว่าจะเก็บไบต์ไหนก่อน เช่น ค่า 0x12345678:

  • Little endian เก็บไบต์ที่มีค่าน้อยสุด (LSB) ก่อน → 78 56 34 12 ใช้ในคอมพิวเตอร์ส่วนบุคคลและมือถือ
  • Big endian เก็บไบต์ที่มีค่ามากสุด (MSB) ก่อน → 12 34 56 78 ใช้ในเครือข่าย IP

จึงมีชื่อเช่น UTF-16LE (little endian) และ UTF-16BE (big endian)

Character encoding กับ code point encoding ต่างกันอย่างไร

สองคำนี้เป็นคนละขั้นกัน:

  • Character encoding คือขั้น “กำหนดเลขให้ตัวอักษร” ตอบคำถามว่าตัวนี้เบอร์อะไร ASCII ทำแค่ขั้นนี้ (A = 65) และเพราะเลขของ ASCII เล็กพอใส่ใน 1 ไบต์ได้เลย จึงไม่ต้องมีขั้นต่อไป ส่วนใน Unicode ขั้นนี้คือชั้น coded character set ที่ให้ code point
  • Code point encoding คือขั้น “แปลงเลข code point ให้เป็นไบต์” ตอบคำถามว่าเลขนี้จะเก็บลงไฟล์เป็นไบต์อะไรบ้าง จำเป็นเพราะ code point ของ Unicode มีได้ถึงกว่าหนึ่งล้านค่า (17 plane × 65,536) ใส่ใน 1 ไบต์ไม่ได้ UTF-8, UTF-16 และ UTF-32 คือวิธีต่าง ๆ ของขั้นนี้

ดังนั้น ASCII จึงเป็นตัวอย่างของ character encoding ส่วน UTF-8 เป็นตัวอย่างของ code point encoding

ASCII เป็นตัวอย่างของ → character encoding · UTF-8 เป็นตัวอย่างของ → code point encoding · เลขเฉพาะไม่ซ้ำของแต่ละตัวอักษรใน Unicode → code point · extended ASCII แสดงเป็นตัวอักษรขยะ → code page ไม่ถูกต้อง

3. พื้นฐาน typography

Typography คือศาสตร์และศิลป์ในการจัดวางตัวอักษรให้อ่านง่ายและสวยงาม ครอบคลุมการเลือก typeface การกำหนดระยะห่างระหว่างตัวอักษรและบรรทัด การจัดแนว และการวางองค์ประกอบในหน้า (typeface คือ “หน้าตา” ส่วน typography คือ “วิธีนำไปใช้”)

หน่วยวัด

  • หน่วยแบบตายตัว (absolute) — point โดย 1 point = 1/72 นิ้ว และ pica โดย 1 pica = 12 point (6 pica = 1 นิ้ว) ใช้บอกขนาดตัวอักษร เช่น 12 pt ซึ่งวัดจากกรอบ (bounding box) ที่ครอบตัวอักษร ไม่ใช่ความสูงของตัวอักษรตัวใดตัวหนึ่ง
  • หน่วยแบบสัมพัทธ์ (relative) — em โดย 1 em เท่ากับขนาด point ของฟอนต์ที่ใช้อยู่ ฟอนต์ 12 pt ก็ 1 em = 12 pt ใช้กำหนดระยะห่าง เช่น ช่องว่างระหว่างคำ 1/4 em ของฟอนต์ 12 pt = 3 pt

ค่าที่ใช้จัดเรียงตัวอักษร (typesetting parameters)

คำความหมาย

ลักษณะของ typeface

  • Serif มีเชิงเล็ก ๆ ที่ปลายเส้น ช่วยให้สายตาไหลตามบรรทัด เหมาะกับเนื้อความยาว เช่น Times New Roman · Sans serif ไม่มีเชิง ดูทันสมัย นิยมใช้กับหัวข้อและบนจอ เช่น Arial
  • Monospace ทุกตัวกว้างเท่ากัน เหมาะกับเขียนโค้ด · Proportional กว้างตามรูปร่าง เช่น i แคบกว่า W
  • Weight ความหนาของเส้น จากบาง (light) ถึงหนา (bold)
  • Italic คือตัวเอียงที่ออกแบบรูปตัวอักษรใหม่ให้เหมือนลายมือ · Oblique คือแค่เอาตัวปกติมาเอียง พบบ่อยในฟอนต์ sans serif เช่น Helvetica
  • Typeface family ชุดของรูปแบบที่ออกแบบให้ใช้ร่วมกัน เช่น regular, bold, italic, bold italic

หน่วยแบบ absolute → point · ข้อยกเว้นระยะห่างของบางคู่ → kerning · “ข้อใดเกี่ยวกับ typography” → ถูกทุกข้อ · ตัวอักษรมีเชิง → serif

1. MEMEX — ต้นกำเนิดของแนวคิด

Memex (ย่อจาก memory expander แปลว่าเครื่องขยายความจำ) เป็นเครื่องในจินตนาการที่ Vannevar Bush เสนอในปี 1945 มีลักษณะเป็นโต๊ะทำงานที่ทำหน้าที่เหมือนห้องสมุดส่วนตัว เก็บเอกสารบนไมโครฟิล์ม ความสามารถของ Memex เทียบกับปัจจุบัน:

Memex ทำได้ปัจจุบันคือ
เครื่องกลขนาดโต๊ะที่เก็บเอกสารบนไมโครฟิล์มมือถือและอินเทอร์เน็ต

เชื่อมเอกสารเข้าด้วยกัน เปิดฉบับหนึ่งแล้วดึงฉบับที่เกี่ยวข้องมาได้ทันทีHyperlink
บันทึกเส้นทางการอ่าน (trail) แล้วคัดลอกส่งให้คนอื่นBookmark, history, การแชร์ลิงก์

ข้อแตกต่างหลัก: ใน Memex ผู้ใช้สร้างลิงก์เอง เป็นของส่วนตัว และแชร์ได้ด้วยการคัดลอก ส่วนบนเว็บ ลิงก์สร้างโดยผู้ให้บริการเนื้อหา เป็นสาธารณะ ข้อมูลกระจายอยู่บนเซิร์ฟเวอร์ทั่วโลกและแชร์ผ่านเครือข่ายโดยไม่ต้องคัดลอก

2. Hypertext, hypermedia และการเข้าถึงแบบไม่เป็นเส้นตรง

Hypertext คือข้อความที่มีลิงก์ไปยังข้อความอื่น hypermedia คือการขยายแนวคิดนี้ไปยังสื่อทุกแบบ ทั้งภาพ เสียง วิดีโอ จุดสำคัญคือทำให้เข้าถึงข้อมูลแบบ non-linear (ไม่เป็นเส้นตรง) ผู้ใช้เลือกเส้นทางเองได้

  • สื่อแบบ linear ต้องดูตามลำดับที่ผู้สร้างกำหนด เช่น ภาพยนตร์ หนังสือ เทปเสียง (audio tape) ที่ต้องกรอเทปไปทีละช่วง
  • สื่อแบบ non-linear กระโดดไปส่วนไหนก็ได้ เช่น เว็บ YouTube เครื่องเล่น MP3 ซีดีเพลงที่กดเลือกแทร็กได้ (หนังสือที่มีสารบัญและดัชนีก็เข้าถึงแบบ non-linear ได้บางส่วน)

Audio CD, YouTube, Web, Audio tape, MP3 player ข้อใดไม่เข้าพวก → audio tape · แนวคิดของเว็บที่มาจาก Memex → hypertext

3. World Wide Web

เว็บถูกสร้างเพื่อให้นักวิทยาศาสตร์ทั่วโลกแบ่งปันข้อมูลกันได้ง่าย ในปี 1990 Tim Berners-Lee ที่ศูนย์วิจัย CERN พัฒนาเว็บเบราว์เซอร์และเว็บเซิร์ฟเวอร์ตัวแรก ชื่อ “web” (ใยแมงมุม) มาจากเอกสารทั่วโลกที่เชื่อมกันด้วยลิงก์

เว็บมีองค์ประกอบหลัก 4 อย่าง:

  1. HTML (HyperText Markup Language) — ภาษาสำหรับเขียนเนื้อหาและโครงสร้างของหน้าเว็บ
  2. HTTP (HyperText Transfer Protocol) — กติกาการรับส่งข้อมูลระหว่างเบราว์เซอร์กับเซิร์ฟเวอร์
  3. URL (Uniform Resource Locator) — ที่อยู่ของทรัพยากร ใช้รูปแบบเดียวกัน (uniform) ไม่ว่าไฟล์อยู่ในเครื่องหรือบนอินเทอร์เน็ต เช่น https://www.example.com/images/cat.jpg ประกอบด้วย โปรโตคอล (https) ชื่อเซิร์ฟเวอร์ (www.example.com) และตำแหน่งไฟล์ (/images/cat.jpg)
  4. DOM (Document Object Model) — โครงสร้างข้อมูลของ element ในหน้าเว็บ (อธิบายในข้อ 5)

“ข้อใดไม่เกี่ยวข้องโดยตรงกับ WWW” (HTTP, URL, DOM, HTML) → ทุกข้อเกี่ยวข้องทั้งหมด

4. Markup language

คำว่า markup มาจากงานพิมพ์ บรรณาธิการเขียนเครื่องหมายบนต้นฉบับบอกช่างเรียงพิมพ์ว่าตรงไหนเป็นหัวข้อ ตัวหนา หรือย่อหน้าใหม่ ในยุคดิจิทัล markup language คือชุดของ tag ที่ใส่โครงสร้างให้เอกสาร คอมพิวเตอร์จึงรู้ว่าข้อมูลแต่ละส่วนคืออะไร แล้วค้นหาหรือดึงข้อมูลเฉพาะส่วนได้ เช่น ดึงชื่อผู้รับจากบันทึก

SGML, HTML และ XML

  • SGML (Standard Generalized Markup Language) — มาตรฐานสำหรับสร้าง markup language อื่น ๆ ซับซ้อนมาก
  • HTML — รุ่นแรก ๆ สร้างตามกฎของ SGML แต่HTML ปัจจุบันกำหนดกฎและมาตรฐานของตัวเองขึ้นใหม่ ไม่อิง SGML แล้ว (ยังเข้ากันได้กับรุ่นเก่า) ดูแลโดยกลุ่ม WHATWG (Web Hypertext Application Technology Working Group) ซึ่งเป็นกลุ่มที่ผู้ผลิตเบราว์เซอร์รายใหญ่ (Apple, Google, Mozilla, Microsoft) ร่วมกันกำหนดมาตรฐาน HTML ในรูปแบบ living standard คือเอกสารมาตรฐานถูกแก้ไขเพิ่มเติมต่อเนื่องเมื่อมีความสามารถใหม่ แทนที่จะออกเป็นเวอร์ชันมีเลขอย่าง 5.1 หรือ 5.2
  • XML — ภาษาที่ย่อและง่ายกว่า SGML ผู้ใช้ตั้งชื่อ tag เองได้ เน้นเก็บโครงสร้างข้อมูล

Procedural กับ descriptive markup

  • Procedural markup บอกว่าข้อความควรหน้าตาอย่างไร เช่น LaTeX, PostScript และ tag รุ่นเก่าของ HTML อย่าง <b> (ตัวหนา) <i> (ตัวเอียง) <font> (รูปแบบตัวอักษร)
  • Descriptive markup บอกว่าข้อความคืออะไร (โครงสร้างและความหมาย) เช่น HTML, XML และ tag อย่าง <p> ที่บอกว่าเป็นย่อหน้า

<p>, <b>, <i>, <font> ข้อใดไม่เข้าพวก → <p> เพราะเป็น descriptive ส่วนที่เหลือเป็น procedural

โครงสร้างของ HTML

เอกสาร HTML ประกอบด้วย element แต่ละ element ระบุด้วย tag เปิดและ tag ปิด เช่น <p>Hello</p> และ element มี attribute ซึ่งเป็นคู่ของชื่อกับค่า เช่น <a href="https://www.it.kmitl.ac.th"> ในที่นี้ href คือชื่อ attribute และ URL คือค่าของ attribute

HTML แสดงสื่อได้หลายแบบ: ข้อความและภาพ · วิดีโอและเสียงด้วย <video> <audio> · Canvas สำหรับวาดและประมวลผลภาพด้วย JavaScript · WebGL สำหรับกราฟิก 3 มิติ · WebXR สำหรับ VR และ AR · ใช้คู่กับ CSS ที่กำหนดการแสดงผล (สี ขนาด ตำแหน่ง) และ JavaScript ที่ทำให้หน้าเว็บโต้ตอบได้

5. DOM และ DOM API

เมื่อเบราว์เซอร์อ่านไฟล์ HTML จะสร้าง DOM ซึ่งเป็นโครงสร้างข้อมูลแบบต้นไม้ (tree) ในหน่วยความจำ แต่ละ tag กลายเป็น node และข้อความกลายเป็น text node ที่อยู่ปลายกิ่ง (leaf) เสมอ

เอกสาร <MEMO> ที่มี <TO>, <FROM>, <BODY> อยู่ข้างใน และใน BODY มี <P> ซึ่งมีข้อความ “The President says,” กับ <Q> อยู่ข้างใน — node ที่มีลูกโดยตรงมากกว่า 1 ตัว คือ MEMO (มี TO, FROM, BODY) และ P (มี text node กับ Q) รวม 2 node (BODY มีลูกตัวเดียวคือ P)

DOM API คือชุดคำสั่งมาตรฐานที่ให้ JavaScript อ่านและแก้ไข DOM ได้ เช่น document.getElementById() หาธาตุตาม id หรือ document.querySelectorAll("p") หาทุกย่อหน้า ใช้ทำสิ่งต่าง ๆ เช่น ควบคุมฟอร์ม canvas วิดีโอและเสียง การลากวาง (drag and drop) การเข้าถึงประวัติการท่องเว็บ และเป็นตัวเชื่อมกับ API อื่น ได้แก่:

  • Web Components — สร้าง tag HTML ของตัวเองที่นำกลับมาใช้ซ้ำได้ เช่น สร้าง <video-player> ที่มีปุ่มควบคุมครบในตัว แล้วใส่ได้ทุกหน้า
  • Web Storage — เก็บข้อมูลในเบราว์เซอร์ (อธิบายในข้อ 6)
  • Web Workers — รันสคริปต์ใน thread แยก (อธิบายในข้อ 6)
  • WebSocket — เปิดช่องสื่อสารสองทางค้างไว้กับเซิร์ฟเวอร์ ส่งข้อมูลไปกลับได้ทันทีโดยไม่ต้องขอใหม่ เหมาะกับแชตและเกมออนไลน์
  • Server-Sent Events (SSE) — เซิร์ฟเวอร์ส่งข้อมูลอัปเดตมาหาเบราว์เซอร์ได้ทางเดียว เหมาะกับการแจ้งเตือนหรือผลบอลสด

6. เบราว์เซอร์แสดงหน้าเว็บอย่างไร

เมื่อเปิดเบราว์เซอร์ จะมีหลาย process ทำงาน เช่น ดูแลเครือข่าย หน้าจอ และพื้นที่เก็บข้อมูล ตัวที่แสดงหน้าเว็บคือ renderer process ซึ่งมี main thread ทำงานเป็นลำดับ:

อ่าน HTML→สร้าง DOM และ CSSOM→รัน JavaScript→คำนวณ layout→วาดพิกเซล (paint)
  1. Parse HTML — อ่านโค้ด HTML ทีละ tag
  2. สร้าง DOM — ต้นไม้ของ element ทั้งหมด (เนื้อหาและโครงสร้าง)
  3. สร้าง CSSOM (CSS Object Model) — อ่าน CSS แล้วสร้างต้นไม้อีกต้นที่บอกว่า element แต่ละตัวมีสไตล์อะไร เช่น สี ขนาดตัวอักษร ระยะห่าง
  4. รัน JavaScript — สคริปต์อาจแก้ DOM หรือสไตล์ผ่าน DOM API เบราว์เซอร์จึงต้องรอให้สคริปต์ทำงานเสร็จก่อน
  5. สร้าง render tree — รวม DOM กับ CSSOM เหลือเฉพาะ element ที่ต้องแสดงจริงพร้อมสไตล์ของมัน
  6. Layout — คำนวณตำแหน่งและขนาดของทุกกล่องบนหน้าจอ เช่น ย่อหน้านี้อยู่ตรงไหน กว้างเท่าไร
  7. Paint — ส่งข้อมูลให้ thread ที่ทำหน้าที่วาด เติมสีลงพิกเซลจริงบนจอ

แต่ละขั้นต้องรอผลจากขั้นก่อนหน้า ดังนั้นถ้า JavaScript คำนวณหนักนาน ขั้นอื่นและการตอบสนองต่อผู้ใช้ต้องรอ หน้าเว็บจึงค้าง

Web worker คือ thread เพิ่มเติมสำหรับรัน script แยกออกไป ปล่อยให้ main thread ดูแลแค่ส่วนติดต่อผู้ใช้ หน้าเว็บจึงไม่ค้าง และใช้ CPU หลายคอร์ได้ดีขึ้น เหมาะกับงานมัลติมีเดียที่ทั้งคำนวณหนัก (ประมวลผลภาพ เสียง วิดีโอ) และต้องตอบสนองทันที

ความสามารถเสริมของเบราว์เซอร์

  • WebGL (Web Graphics Library) — ทำให้ JavaScript สั่ง GPU วาดกราฟิก 2 และ 3 มิติลงใน <canvas> ได้ เบื้องหลังคือ OpenGL ซึ่งเป็นมาตรฐานกลางสำหรับสั่งงาน GPU ให้วาดกราฟิก 3 มิติ และ OpenGL ES (ES ย่อจาก embedded systems) คือ OpenGL รุ่นย่อสำหรับอุปกรณ์เล็กอย่างมือถือ WebGL นำ OpenGL ES มาใช้ในเบราว์เซอร์ คำนวณโดย GPU จึงเร็วพอสำหรับเกม 3 มิติหรือแผนที่ 3 มิติบนเว็บ โดยไม่ต้องลงปลั๊กอิน
  • Push technologies — ปกติเบราว์เซอร์ต้องส่งคำขอทุกครั้งที่อยากได้ข้อมูลใหม่ (polling) แต่ WebSocket และ Server-Sent Events (SSE) ให้เซิร์ฟเวอร์ส่งข้อมูลใหม่มาเองเมื่อมีอัปเดต เหมาะกับแชตหรือการแจ้งเตือน
  • Web Storage — เก็บข้อมูลในเบราว์เซอร์ฝั่งผู้ใช้ ประมาณ 5–10 MB ต่อเว็บไซต์ มี localStorage (เก็บถาวร) และ sessionStorage (หายเมื่อปิดแท็บ)

CH11 · เครือข่ายมัลติมีเดียและความปลอดภัย

แอปมัลติมีเดียบนเครือข่ายมีกี่แบบ real-time คืออะไร โปรโตคอลสตรีมมิงแต่ละตัวทำงานอย่างไร และปกป้องลิขสิทธิ์วิดีโอได้อย่างไร

1. ประเภทของแอปมัลติมีเดียบนเครือข่าย

  • Interactive multimedia — ผู้ใช้โต้ตอบกันสด ๆ เช่น โทรผ่านอินเทอร์เน็ต (VoIP) ประชุมวิดีโอ (Zoom) เกมออนไลน์ ความล่าช้าแม้นิดเดียวก็รู้สึกได้ จึงต้องการ real-time เข้มงวดที่สุด
  • Streaming multimedia — รับชมหรือฟังต่อเนื่อง เช่น Spotify, YouTube, Netflix ยอมให้หน่วงได้บ้างเพราะโหลดล่วงหน้าไว้ได้ แต่ยังต้องส่งทันเวลาเล่น มีทั้งแบบถ่ายทอดสด (live) และแบบเลือกดูเมื่อไรก็ได้ (on-demand)

Prime Video, YouTube, Netflix, Zoom, Spotify ข้อใดไม่เข้าพวก → Zoom เพราะเป็น interactive

2. Real-time คืออะไร

ระบบ real-time คือระบบที่ต้องส่งข้อมูลจำนวนหนึ่งให้ถึงทันเวลาภายในช่วงเวลาที่กำหนด (deadline) สำคัญกับมัลติมีเดียเพราะผู้ใช้ปลายทางคือคน ถ้าเสียงมาช้าก็คุยกันไม่รู้เรื่อง แบ่งเป็น 3 ระดับตามผลเมื่อพลาด deadline:

ประเภทถ้าพลาด deadlineตัวอย่าง
Hard real-timeระบบล้มเหลวทันที จึงต้องทันเวลาเสมอระบบควบคุมเครื่องยนต์เครื่องบิน
Firm real-timeพลาดได้บางครั้ง คุณภาพลดลง แต่ระบบไม่ล้มVideo streaming เช่น Netflix (เฟรมมาช้าก็ข้ามไป)
Soft real-timeพลาดแล้วระบบไม่ล้ม และผลลัพธ์ยังใช้ประโยชน์ได้เก็บข้อมูลจากเซนเซอร์สภาพอากาศ

นิยามของ hard real-time → ระบบทำงานที่ระบุได้ภายในระยะเวลาที่กำหนดเสมอ ไม่ใช่ “ถูกทุกข้อ” และไม่ใช่ “เร็วจนไม่เห็น delay” (ข้อนี้คุณเคยตอบผิด)

คุณภาพบริการของเครือข่าย (QoS — quality of service)

  • Bandwidth คือความจุสูงสุดของช่องสัญญาณ เช่น เน็ต 100 Mbps · Throughput คืออัตราที่ส่งข้อมูลได้จริง ซึ่งมักต่ำกว่า เช่น ได้จริง 80 Mbps แอปวิดีโอต้องการ throughput เฉลี่ยมากพอกับ bit rate ของวิดีโอ
  • ความเร็วคงที่หรือไม่ (bit rate variation) — CBR (constant bit rate) ส่งข้อมูลด้วยอัตราเท่ากันตลอด เช่น เสียงโทรศัพท์ VoIP ที่ใช้ข้อมูลเท่า ๆ กันทุกวินาที วางแผนเครือข่ายง่าย · VBR (variable bit rate) อัตราขึ้นลงตามเนื้อหา เช่น วิดีโอฉากนิ่งใช้ข้อมูลน้อย ฉากแอ็กชันใช้ข้อมูลมาก ประหยัดกว่าแต่เครือข่ายต้องรับช่วงที่พุ่งสูงได้
  • Latency (ความหน่วง) — เวลาที่ packet ใช้เดินทางจากต้นทางถึงปลายทาง หน่วยมิลลิวินาที ยิ่งต่ำยิ่งตอบสนองไว โทรผ่านเน็ตเริ่มรู้สึกช้าเมื่อเกินราว 150–300 มิลลิวินาที
  • Jitter (ความรู้เสริม สไลด์พูดถึงแค่ว่า latency ขึ้นกับความเร็วที่เปลี่ยนไปตามเวลา) — ความไม่สม่ำเสมอของ latency เช่น packet หนึ่งใช้ 20 มิลลิวินาที อีกอันใช้ 120 มิลลิวินาที ทำให้มาถึงไม่เป็นจังหวะ เสียงและภาพจึงกระตุก ผู้รับแก้โดยเก็บข้อมูลไว้ใน buffer ก่อนเล่นเล็กน้อย

3. โปรโตคอลและเลเยอร์

เริ่มจาก: โปรโตคอลคืออะไร และเลเยอร์คืออะไร

โปรโตคอล (protocol) คือกติกาการสื่อสารที่ฝั่งส่งและฝั่งรับตกลงใช้ร่วมกัน เช่น ต้องขอก่อนแล้วค่อยส่ง ข้อมูลหายต้องทำอย่างไร

การส่งข้อมูลบนอินเทอร์เน็ตแบ่งงานเป็นชั้น ๆ (layer) แต่ละชั้นรับผิดชอบงานคนละอย่าง และใช้บริการของชั้นที่อยู่ข้างล่าง โปรโตคอลแต่ละตัวจึง “อยู่” ในชั้นใดชั้นหนึ่งตามงานที่มันทำ

นึกถึงการส่งพัสดุ: ชั้นแอปพลิเคชันคือเนื้อหาในกล่องและข้อตกลงระหว่างผู้ส่งกับผู้รับ เช่น “กล่องนี้เป็นวิดีโอตอนที่ 3 ความละเอียด 720p” · ชั้นขนส่งคือบริษัทขนส่งที่เลือกได้ว่าจะส่งแบบลงทะเบียน (ตามจนกว่าจะถึง แต่ช้า) หรือแบบด่วนธรรมดา (เร็ว แต่หายก็หาย) · ชั้นอินเทอร์เน็ต (IP)คือระบบที่อยู่และเส้นทางที่พากล่องไปถึงบ้านปลายทาง

สไลด์บอกว่าสำหรับแอปมัลติมีเดีย มี 2 ชั้นที่สำคัญ คือชั้นขนส่ง (transport layer) และชั้นแอปพลิเคชัน (application layer) และมีโปรโตคอลบางตัวที่อยู่ตรงกลางระหว่างสองชั้นนี้ ภาพรวมเป็นแบบนี้ (ชั้นบนสุดอยู่ใกล้ผู้ใช้ที่สุด):

ชั้นทำหน้าที่โปรโตคอลที่อยู่ชั้นนี้

ชั้นแอปพลิเคชัน		กติกาที่แอปใช้คุยกันโดยตรง เช่น “ขอไฟล์นี้” “เริ่มเล่น” “หยุด” “โทรหาคนนี้”HTTP, HLS, DASH, RTSP, RTMP, WebRTC, SIP, H.323
ระหว่างชั้นเตรียมข้อมูลภาพและเสียงให้พร้อมส่งแบบ real-time (ติดเลขลำดับและเวลา) และรายงานคุณภาพRTP, RTCP

ชั้นขนส่ง: TCP กับ UDP

TCP (Transmission Control Protocol) เหมือนส่งพัสดุแบบลงทะเบียน ฝั่งรับต้องตอบกลับว่าได้รับแล้ว ถ้า packet ไหนหายจะส่งซ้ำจนกว่าจะครบ และเรียงลำดับให้ถูก ข้อมูลจึงครบแน่นอนแต่อาจช้า เหมาะกับงานที่ขาดส่วนไม่ได้ เช่น เปิดหน้าเว็บ ดาวน์โหลดไฟล์ และสตรีมที่บัฟเฟอร์ล่วงหน้าได้ (HTTP, HLS, DASH, RTMP ทำงานบน TCP)

UDP (User Datagram Protocol) เหมือนโยนของไปเรื่อย ๆ ไม่รอตอบกลับ ไม่ส่งซ้ำ จึงเร็วแต่อาจหายบ้าง เหมาะกับงาน real-time เพราะในการคุยสด เสียงที่หายไปครึ่งวินาที ถ้าส่งซ้ำมาถึงทีหลังก็ไม่มีประโยชน์แล้ว เพราะบทสนทนาผ่านไปแล้ว ยอมเสียงขาดนิดหน่อยดีกว่ารอ

QUIC (เดิมย่อจาก Quick UDP Internet Connection) สร้างบน UDP แต่เพิ่มการตรวจความครบและการเข้ารหัสเข้าไปเอง ได้ความเร็วแบบ UDP และความน่าเชื่อถือใกล้ TCP ใช้เป็นฐานของ HTTP/3

ระหว่างชั้น: RTP และ RTCP

UDP ส่ง packet ออกไปเฉย ๆ ฝั่งรับไม่รู้ว่า packet ไหนมาก่อนหลัง หรือควรเล่นตอนไหน จึงมีโปรโตคอลมาเสริมอยู่เหนือ UDP:

  • RTP (Real-time Transport Protocol) — ติดเลขลำดับและเวลา (timestamp) ลงบนทุก packet ของภาพและเสียง ฝั่งรับจึงเรียงใหม่ได้ รู้ว่าอันไหนหาย และเล่นแต่ละชิ้นตรงเวลา สรุปคือ RTP เป็นตัวขนส่งข้อมูลภาพและเสียงจริง
  • RTCP (Real-time Control Protocol) — ทำงานคู่กับ RTP คอยรายงานคุณภาพกลับไปฝั่งส่ง เช่น packet หายกี่เปอร์เซ็นต์ หน่วงเท่าไร ฝั่งส่งจะได้ปรับคุณภาพได้

RTP และ RTCP ไม่ได้ตัดสินว่าจะเล่นอะไร หยุดตอนไหน หรือโทรหาใคร (นั่นเป็นงานของชั้นแอปพลิเคชัน) แต่ก็ไม่ได้เป็นตัวขนส่งพื้นฐานแบบ UDP สไลด์จึงจัดให้อยู่ระหว่างชั้นขนส่งกับชั้นแอปพลิเคชัน

ชั้นแอปพลิเคชัน กลุ่ม A: สำหรับโทรและประชุมวิดีโอ

งานกลุ่มนี้มี 2 ลักษณะ: สื่อสารสองทาง (ทุกคนทั้งพูดและฟัง) และต้องหน่วงน้อยมาก (เกินครึ่งวินาทีก็คุยกันลำบากแล้ว)

  • SIP (Session Initiation Protocol) — ทำหน้าที่ตั้งค่าและจัดการการโทร เหมือนการกดเบอร์ ให้อีกฝั่งรับสาย และวางสาย ส่วนเสียงและภาพจริงเดินทางผ่าน RTP ใช้ในระบบโทรศัพท์ผ่านอินเทอร์เน็ต (VoIP)
  • H.323 — ชุดมาตรฐานรุ่นเก่าสำหรับประชุมวิดีโอ ครอบคลุมตั้งแต่การตั้งสาย การควบคุมสื่อ จนถึง codec พบในอุปกรณ์ประชุมทางไกลในห้องประชุม
  • WebRTC (Web Real-Time Communication) — ทำให้เบราว์เซอร์คุยด้วยภาพและเสียงกันได้ตรง ๆ แบบ real-time โดยไม่ต้องลงโปรแกรมเสริม เช่น Google Meet และ Discord เพราะหน่วงต่ำมาก จึงถูกใช้สตรีมที่ต้องการความหน่วงต่ำมากด้วย นี่คือเหตุผลที่ WebRTC อยู่ในทั้งสองกลุ่ม

ชั้นแอปพลิเคชัน กลุ่ม B: สำหรับสตรีมวิดีโอ

งานกลุ่มนี้ส่งทางเดียว จากเซิร์ฟเวอร์หรือกล้องไปหาผู้ชม จึงยอมให้หน่วงได้มากกว่า (รายละเอียดแต่ละตัวอยู่ในหัวข้อ 4–6 ถัดไป)

  • HTTP (HyperText Transfer Protocol) — โปรโตคอลปกติของเว็บ ใช้ขอไฟล์จากเซิร์ฟเวอร์ ในงานสตรีมใช้ดาวน์โหลดไฟล์วิดีโอทั้งไฟล์แบบเล่นไปโหลดไป (progressive download)
  • HLS และ DASH — ทำงานบน HTTP อีกที เพิ่มกติกาว่าวิดีโอต้องหั่นเป็นชิ้นสั้น ๆ มีไฟล์ดัชนีบอกรายการชิ้น และผู้ชมเลือกความละเอียดตามความเร็วเน็ตได้ ต้องรอให้ชิ้นถูกสร้างเสร็จก่อน จึงหน่วงหลายวินาที
  • RTSP (Real-time Streaming Protocol) — ทำหน้าที่เหมือนรีโมตควบคุม ส่งคำสั่ง เล่น หยุดชั่วคราว หยุด ไปยังเซิร์ฟเวอร์ ส่วนภาพและเสียงจริงส่งมาด้วย RTP ใช้กับกล้อง IP และกล้องวงจรปิด
  • RTMP (Real-time Messaging Protocol) — เปิดการเชื่อมต่อค้างไว้แล้วส่งสตรีมสดต่อเนื่อง ปัจจุบันใช้ส่งวิดีโอจากผู้ถ่ายทอดขึ้นแพลตฟอร์ม เช่น OBS ไป YouTube
  • WebRTC — ใช้สตรีมที่ต้องการความหน่วงต่ำมากได้ด้วย (ตามที่อธิบายในกลุ่ม A)

ทำไมเฉลยจึงเป็นแบบนั้น

โจทย์: HTTP, RTSP, RTP, WebRTC, HLS ข้อใดไม่เข้าพวกตามเลเยอร์

เทียบกับตารางข้างบน: HTTP, RTSP, WebRTC และ HLS อยู่ชั้นแอปพลิเคชันทั้งหมด เพราะเป็นกติกาที่แอปใช้สั่งงานกัน ส่วน RTP อยู่ระหว่างชั้นขนส่งกับชั้นแอปพลิเคชัน เพราะมันแค่ขนข้อมูลภาพและเสียงให้โปรโตคอลชั้นบน เฉลยจึงเป็น RTP

ที่คนมักตอบ HTTP เพราะรู้สึกว่า HTTP เป็น “โปรโตคอลเว็บทั่วไป” ไม่ใช่ของสตรีมมิง แต่โจทย์ถามเรื่องชั้น ไม่ได้ถามเรื่องการใช้งาน และ HTTP ก็อยู่ชั้นแอปพลิเคชันเหมือนตัวอื่น

โจทย์: ข้อใดเป็น protocol ที่เหมาะกับ video conferencing app (DASH, RTSP, WebRTC, ถูกทุกข้อ, HLS)

การประชุมต้องสื่อสารสองทางและหน่วงน้อยมาก DASH และ HLS ต้องรอหั่นวิดีโอเป็นชิ้นก่อน หน่วงหลายวินาที คุยกันไม่ได้ ส่วน RTSP ออกแบบมาให้ผู้ชมสั่งเล่นและหยุดสตรีมทางเดียว จากกล้องหรือเซิร์ฟเวอร์ ไม่ใช่ให้คนหลายคนคุยกัน จึงเหลือ WebRTC ที่ออกแบบมาเพื่อคุยสดสองทางโดยตรง (สไลด์จัด WebRTC ไว้คู่กับ H.323 และ SIP ในกลุ่ม VoIP และประชุมวิดีโอ)

4. เทคนิคสตรีมมิง 3 แบบ

ส่วนใหญ่ต้องมี media server (อาจเป็นส่วนหนึ่งของเว็บเซิร์ฟเวอร์ถ้าใช้ HTTP)

4.1 Pseudo-streaming หรือ progressive download — ใช้ HTTP

วางไฟล์วิดีโอบนเว็บเซิร์ฟเวอร์ธรรมดา เบราว์เซอร์ดาวน์โหลดแบบเดียวกับเนื้อหาเว็บอื่น ๆ แต่เริ่มเล่นได้ระหว่างที่ยังโหลดไม่เสร็จ ไฟล์มักเป็น MP4 ซึ่งประกอบด้วยหน่วยข้อมูลเรียกว่า atom โดย moov atom เก็บข้อมูลวิธีเล่น เช่น ขนาดภาพและจำนวนเฟรมต่อวินาที ต้องย้าย moov atom ไปไว้ต้นไฟล์ เบราว์เซอร์จึงรู้วิธีเล่นตั้งแต่ไบต์แรก ๆ และเริ่มเล่นได้ทันที

4.2 True streaming — ใช้ RTSP หรือ RTMP

RTSP (Real-time Streaming Protocol) เก่ามาก ใช้ตั้งแต่ยุคแรกของการสตรีม (RealNetworks) ปัจจุบันเป็นมาตรฐานของกล้อง IP และกล้องวงจรปิด ต้องมี RTSP server และใช้คู่กับ RTP, RTCP บน UDP

RTMP (Real-time Messaging Protocol) สร้างโดย Macromedia (ภายหลังเป็นของ Adobe ยุค Flash) รองรับความหน่วงทั้งปกติ ต่ำ และต่ำมาก แต่มีปัญหาเรื่องความเข้ากันได้กับอุปกรณ์ ปัจจุบันจึงใช้หลัก ๆ เพื่อ ingest คือส่งวิดีโอสดจากผู้ถ่ายทอดขึ้นไปยังแพลตฟอร์ม เช่น จาก OBS ไป YouTube · RTMPS คือ RTMP ที่เข้ารหัส

4.3 Video segmented streaming — ใช้ HLS หรือ DASH

หั่นวิดีโอเป็นไฟล์ชิ้นสั้น ๆ (segment) ทำไว้หลายความละเอียด แล้วมีไฟล์ดัชนี (manifest) บอกรายการชิ้นทั้งหมด ผู้ชมขอทีละชิ้นผ่าน HTTP และเลือกความละเอียดตามความเร็วเน็ต เรียกว่า adaptive bitrate streaming

“ข้อใดไม่ใช่ video streaming technique” → soft real-time streaming (ไม่มีจริง) · pseudo-streaming ใช้ → HTTP

5. HLS แบบละเอียด

HLS (HTTP Live Streaming) พัฒนาโดย Apple นิยมที่สุดและใช้ได้ทุกแพลตฟอร์ม ใช้ทั้งถ่ายทอดสดและ adaptive streaming

กล้อง (เสียงและภาพ)→Media encoder→ MPEG-2 TS →Stream segmenter→Origin web server (index + segments)→ HTTP →ผู้ชม
  1. Encode — บีบอัดภาพด้วย H.264 (codec บีบอัดวิดีโอที่ใช้แพร่หลายที่สุด เล่นได้แทบทุกอุปกรณ์) และบีบอัดเสียงด้วย AAC หรือ MP3 (codec เสียงแบบ lossy จาก CH8) แล้วห่อภาพและเสียงรวมกันในรูปแบบ MPEG-2 transport stream (TS) ซึ่งเป็น “กล่องบรรจุ” (container) ที่ออกแบบมาสำหรับส่งออกอากาศต่อเนื่อง ตัดเป็นช่วง ๆ ได้ง่าย (codec คือวิธีบีบอัด ส่วน container คือกล่องที่ใส่ข้อมูลที่บีบอัดแล้ว)
  2. HLS server ประมวลผล — แบ่ง (segmenting) เป็นชิ้นสั้น ๆ ไม่กี่วินาที · ทำหลายเวอร์ชันตาม bitrate (adapting) · จัดแพ็กไฟล์ (packaging)
  3. สร้างไฟล์ดัชนี (manifest) รูปแบบ M3U (.m3u8) บอกรายการ segment ความยาวแต่ละชิ้น และลำดับการเล่น
  4. Segment เป็นไฟล์ .ts (ชิ้นของ MPEG-2 TS) หรือ .m4s (fragmented MP4 คือ MP4 ที่แบ่งเป็นชิ้นสั้น ๆ ที่แต่ละชิ้นเล่นต่อกันได้เอง ต่างจาก MP4 ธรรมดาที่ต้องมี moov atom ของทั้งไฟล์) เก็บบนเว็บเซิร์ฟเวอร์และกระจายผ่าน CDN
  5. ผู้ชม โหลด manifest ก่อน → ขอ segment ทีละชิ้น → วัดความเร็วเน็ต → เลือกความละเอียดของชิ้นถัดไป → เล่นต่อเนื่อง ตัวอย่างผู้ใช้คือ Twitch

6. DASH แบบละเอียด

DASH (Dynamic Adaptive Streaming over HTTP) หลักการเหมือน HLS แต่เป็นมาตรฐานของกลุ่ม MPEG ไฟล์ดัชนีเรียกว่า MPD (Media Presentation Description) เขียนด้วย XML สไลด์ระบุว่า segment มักเป็น .ts ใช้โดย YouTube ฝั่งผู้ชมมี 3 ส่วน:

  • HTTP access client — ส่งคำขอ segment ตาม URL ใน MPD
  • DASH control engine — “สมอง” ที่ดูความเร็วเน็ตและปริมาณบัฟเฟอร์ แล้วตัดสินใจว่าชิ้นถัดไปควรเป็นความละเอียดเท่าไร
  • Media engines — ถอดรหัสและเล่นชิ้นต่อกันให้ต่อเนื่อง

ข้อใดทำงานใกล้เคียง HLS → DASH (ไม่ใช่ RTSP)

7. การถ่ายทอดสดครบวงจร และ CDN

กล้องหรือ OBS→ ingest ด้วย RTMP →Media server: transcode + package→ egress →CDN→ delivery ด้วย HLS หรือ DASH →ผู้ชม

ในแผนภาพ ingest คือขาที่วิดีโอไหลเข้า media server และ egress คือขาที่วิดีโอที่ประมวลผลแล้วไหลออกจาก media server ไปยัง CDN

Ingestion protocol คือโปรโตคอลที่ส่งวิดีโอขึ้นไปยัง media server เพื่อ transcode และจัดแพ็ก ก่อนแจกจ่ายให้ผู้ชม Transcoding คือการเข้ารหัสใหม่ด้วย codec ที่เหมาะกับการส่ง (และทำหลายความละเอียด) โปรโตคอลที่ใช้แจกจ่ายก็ใช้ ingest ได้:

Ingest protocolเข้ารหัสCodec ภาพหมายเหตุ
RTMPไม่H.264ใช้ได้ทั้งความหน่วงปกติ ต่ำ และต่ำมาก
RTMPSใช่H.264เหมือน RTMP แต่ปลอดภัย
HLSใช่H.264, H.265 (HEVC)ดีสำหรับ 4K รองรับ HDR แต่ไม่เหมาะกับความหน่วงต่ำมาก
DASHใช่H.264, VP9ดีสำหรับ 4K แต่ไม่เหมาะกับความหน่วงต่ำมาก

คำในตาราง: H.265 (หรือ HEVC) คือ codec วิดีโอรุ่นถัดจาก H.264 บีบอัดได้ดีกว่าที่คุณภาพเท่ากัน จึงเหมาะกับวิดีโอ 4K ที่ไฟล์ใหญ่ · VP9 คือ codec วิดีโอของ Google ที่บีบอัดได้ในระดับใกล้เคียงกัน · HDR (high dynamic range) คือวิดีโอที่เก็บช่วงความสว่างจากมืดสุดถึงสว่างสุดได้กว้างกว่าปกติ · ultra-low latency หมายถึงหน่วงต่ำมากจนเกือบเป็น real-time ซึ่ง HLS และ DASH ทำไม่ได้เพราะต้องรอหั่นชิ้นก่อน

CDN (content distribution network) คือเครือข่ายเซิร์ฟเวอร์ที่กระจายอยู่ทั่วโลก เก็บสำเนา (cache) ของ segment ไว้ เมื่อผู้ชมกด play คำขอจะถูกส่งไปเซิร์ฟเวอร์ที่ใกล้ที่สุด ถ้าคนดูน้อย media server ส่งเองได้ แต่ถ้าคนดูมากต้องใช้ CDN

Protocol ที่ใช้ส่งวิดีโอจากเครื่องผู้ใช้ไป YouTube เพื่อ live → ingestion protocol

8. ความปลอดภัยของมัลติมีเดีย

ความปลอดภัยของเครือข่ายและระบบ

เข้ารหัสข้อมูลระหว่างทาง ด้วย HTTPS, RTMPS หรือส่ง HLS และ DASH บนชั้นขนส่งที่เข้ารหัส และควบคุมการเข้าถึง (network access control) ด้วย 3 อย่าง:

  • Key (กุญแจ) — ข้อมูลลับที่ใช้เข้ารหัสและถอดรหัส หรือยืนยันสิทธิ์ เช่น stream key ที่ YouTube ให้มาใส่ใน OBS ใครมี stream key ก็ส่งสตรีมขึ้นช่องนั้นได้ จึงต้องเก็บเป็นความลับ
  • Certificate (ใบรับรอง) — เอกสารดิจิทัลที่ยืนยันว่าเซิร์ฟเวอร์เป็นตัวจริง ออกโดยหน่วยงานที่น่าเชื่อถือ (certificate authority) เมื่อเข้า HTTPS เบราว์เซอร์ตรวจ certificate ก่อน จึงมั่นใจได้ว่าไม่ได้คุยกับเว็บปลอม
  • Password (รหัสผ่าน) — วิธีพื้นฐานในการยืนยันตัวผู้ใช้ก่อนให้เข้าถึงบัญชีหรือเนื้อหา

DRM (digital rights management)

DRM คือเทคโนโลยีที่ทำให้เนื้อหาที่มีลิขสิทธิ์ถูกใช้เฉพาะโดยผู้ที่ได้รับอนุญาต และใช้ตามที่อนุญาตเท่านั้น ควบคุม 4 เรื่อง: ใคร (who) ทำอะไรได้ (what) เมื่อไร (when) และที่ไหน (where) ระบบที่นิยม:

  • Widevine (Google) — Chrome, Firefox, Edge บน Windows, Mac, Linux และ Android, Android TV, Chromecast
  • FairPlay (Apple) — Safari บน Mac และ iOS และแอป iOS
  • PlayReady (Microsoft) — Edge และ Windows

การเข้ารหัสวิดีโอใน DRM: วิดีโอถูกแปลงเป็นรูปแบบที่ผู้ชมเปิดไฟล์ดิบไม่ได้ และกุญแจถอดรหัสถูกซ่อนไว้ในกล่องดำ (black box) Google และ Apple ควบคุมเบราว์เซอร์และระบบปฏิบัติการของตัวเอง จึงคุมความปลอดภัยของกลไกนี้ได้ดี

เบราว์เซอร์เล่นวิดีโอที่ล็อกด้วย DRM ได้อย่างไร (EME และ CDM)

มี 3 ส่วนทำงานร่วมกัน:

  • CDM (Content Decryption Module) — ซอฟต์แวร์ปิด (กล่องดำ) ที่ติดมากับเบราว์เซอร์ เป็นส่วนเดียวที่ถือกุญแจและถอดรหัสวิดีโอได้ เช่น Chrome มี CDM ของ Widevine
  • EME (Encrypted Media Extensions) — มาตรฐานของเบราว์เซอร์ที่เป็นช่องทางสื่อสารระหว่างหน้าเว็บกับ CDM หน้าเว็บสั่งงานผ่าน EME ได้ แต่แตะกุญแจเองไม่ได้ ทำให้เล่นวิดีโอ DRM ได้โดยไม่ต้องลงปลั๊กอิน
  • License server — เซิร์ฟเวอร์ของผู้ให้บริการ ตรวจว่าผู้ใช้มีสิทธิ์ดูหรือไม่ แล้วส่งกุญแจให้ CDM
หน้าเว็บโหลดวิดีโอที่เข้ารหัส→เบราว์เซอร์พบว่าล็อก จึงเรียก CDM ผ่าน EME→CDM สร้างคำขอใบอนุญาต→หน้าเว็บส่งคำขอไป license server→server ตรวจสิทธิ์ แล้วส่งกุญแจกลับ→CDM ถอดรหัสและส่งภาพให้เล่น

กุญแจอยู่ใน CDM ตลอด ผู้ใช้และหน้าเว็บจึงดึงไฟล์วิดีโอที่ถอดรหัสแล้วออกมาไม่ได้ · OCDM (Open Content Decryption Module) คือ CDM ที่เพิ่มส่วนเชื่อมต่อมาตรฐานไปยัง DRM platform ทำให้นำไปใช้กับหลายระบบ DRM และอุปกรณ์อย่างสมาร์ตทีวีได้ง่ายขึ้น

Forensic watermarking (ลายน้ำดิจิทัลเพื่อการพิสูจน์)

Netflix ใช้ทั้งการเข้ารหัส (รวม EME) และ forensic watermark คือฝังข้อมูลที่มองไม่เห็น เช่น user id และ IP address ลงในวิดีโอของแต่ละคน ถ้ามีคนอัดหน้าจอแล้วนำไปเผยแพร่ ก็ตรวจลายน้ำแล้วสืบกลับไปหาบัญชีหรืออุปกรณ์ต้นทางได้ ใช้เป็นหลักฐานทางกฎหมาย ขั้นตอน: ฝังลายน้ำ → ซอฟต์แวร์สแกนตรวจพบ → ถอดข้อมูลออกมา

CH12 · อุปกรณ์มัลติมีเดีย

ระบบคอมพิวเตอร์มัลติมีเดียทำงานอย่างไร หน่วยประมวลผลแต่ละแบบต่างกันอย่างไร จอแสดงผลวัดคุณภาพจากอะไร และเซนเซอร์รับข้อมูลมีอะไรบ้าง (บทนี้ไม่มีแบบฝึกหัดในไฟล์ของคุณ จึงเรียบเรียงจากสไลด์)

1. ระบบคอมพิวเตอร์มัลติมีเดีย

Capture→Digitize→Process→Store หรือ Transmit→Present
  1. Capture (รับ) — อุปกรณ์รับข้อมูลจับปรากฏการณ์ทางกายภาพ ได้แก่ แสง เสียง การสัมผัส การเคลื่อนไหว ด้วยกล้อง ไมโครโฟน จอสัมผัส และเซนเซอร์
  2. Digitize (แปลงเป็นดิจิทัล) — สุ่มค่า (sampling) และปัดค่า (quantization) ด้วย ADC (analog-to-digital converter) ส่วนภาพจากกล้องผ่าน ISP (image signal processor)
  3. Process (ประมวลผล) — CPU, GPU และ NPU เรนเดอร์ กรอง วิเคราะห์ บีบอัด และคลายการบีบอัด
  4. Store และ transmit (เก็บและส่ง) — บีบอัดด้วย codec แล้วเก็บเป็นไฟล์หรือส่งผ่านเครือข่าย
  5. Present (แสดงผล) — อุปกรณ์แสดงผล (จอ ลำโพง อุปกรณ์สั่นสัมผัส) แปลงข้อมูลกลับเป็นสิ่งที่ประสาทสัมผัสรับรู้ได้

ประเภทอุปกรณ์มัลติมีเดีย: computing devices (คอมพิวเตอร์ส่วนบุคคล แท็บเล็ต สมาร์ตโฟน และอุปกรณ์ฝังตัว เช่น เครื่องเล่นเกม กล่องทีวี สมาร์ตทีวี Apple Vision Pro, Oculus Quest) · multimedia processing devices (GPU, NPU) · display devices · input devices

2. GPU (graphics processing unit)

เดิมออกแบบมาเพื่อเร่งการเรนเดอร์กราฟิก 3 มิติ ปัจจุบันใช้กับงานคำนวณหนักที่แบ่งทำพร้อมกันได้ (parallel) เช่น เกม การสร้างและตัดต่อวิดีโอ และ machine learning

CPU ต่างจาก GPU อย่างไร: CPU มี core ไม่กี่ตัวแต่แต่ละตัวทรงพลัง มี cache และวงจรควบคุมขนาดใหญ่ เหมาะกับงานทั่วไปที่ต้องตัดสินใจเป็นลำดับ ส่วน GPU มีcore เรียบง่ายนับพันตัว เหมาะกับงานที่ทำสิ่งเดียวกันกับข้อมูลจำนวนมากพร้อมกัน เช่น คำนวณสีของพิกเซลนับล้าน

ความสามารถของ GPU สมัยใหม่: ray tracing จำลองการเดินทางของแสงให้ภาพ 3 มิติสมจริง · AI upscaling ขยายความละเอียด เช่น 2K เป็น 4K และสร้างเฟรมแทรก (frame interpolation) · media engine ฮาร์ดแวร์ถอดรหัสและเข้ารหัสวิดีโอ

3. NPU (neural processing unit)

NPU คือหน่วยประมวลผลที่ออกแบบมาเพื่อรันโครงข่ายประสาทเทียม (AI) โดยเฉพาะ ชื่อทางการค้า เช่น Neural Engine (Apple), Hexagon NPU (Qualcomm), TPU (Google) งานหลักของ AI คือการคูณเมทริกซ์ ซึ่งประกอบจากการคูณแล้วบวกสะสม (MAC — multiply-accumulate) จำนวนมหาศาล NPU ทำ MAC ด้วยความละเอียดตัวเลขที่ต่ำกว่า GPU จึงประหยัดพลังงานกว่า GPUสำหรับงานนี้

ในมือถือ NPU อยู่บน SoC (system-on-chip) ร่วมกับ CPU, GPU, ISP (กล้อง), DSP (เสียง) และ media engine โดยใช้หน่วยความจำ DRAM (LPDDR) ร่วมกัน

Lossy Audio Compression & Masking

หัวข้อที่ได้โจทย์จริงมาแล้ว — ต้องเขียนได้คล่องที่สุด

จากกระบวนการบีบอัดเสียงแบบสูญเสียข้อมูล (Perceptual Audio Coding) ขั้นตอนที่ 3 (การกำหนดจำนวนบิตโดยใช้ Psychoacoustic Model) ถือเป็นหัวใจสำคัญ จงอธิบายว่า Frequency Masking และ Temporal Masking คืออะไร และช่วยลดจำนวนบิตในกระบวนการ Quantization ได้อย่างไร โดยเชื่อมโยงว่าขั้นตอนที่ 1 (Filter bank 32 ตัว) และขั้นตอนที่ 2 (จัดกลุ่ม 12 samples) จำเป็นต่อการวิเคราะห์ masking อย่างไร (7 คะแนน)

ภาพรวมที่ต้องมีในหัว

1. 32 band-pass filters→2. จัดกลุ่ม 12 samples/band (32×12 = 384)→3. Psychoacoustic model → bit allocation→4. เก็บ bits, scale factor, quantized data

หลักคิดเดียวของ lossy: ไม่ต้องเก็บสิ่งที่หูไม่ได้ยิน และ ปล่อยให้มี quantization noise ได้ ตราบใดที่ noise ยังเบาจนหูไม่ได้ยิน

1) Frequency masking คือปรากฏการณ์ที่เสียงดัง (masker) ทำให้หูไม่ได้ยินเสียงที่เบากว่า (maskee) ซึ่งอยู่ในย่านความถี่ใกล้เคียงและเกิดขึ้นพร้อมกัน เพราะ masker ยกระดับ threshold of hearing ในย่านความถี่รอบตัวมันสูงขึ้น เกิดเป็น masking threshold ใหม่ ยิ่ง masker ดังเท่าไร ช่วงความถี่ที่ถูกบังก็ยิ่งกว้าง

2) Temporal masking คือการที่เสียงดังบังเสียงเบาที่เกิดในช่วงเวลาใกล้กัน แบ่งเป็น pre-masking บังเสียงที่เกิดก่อนหน้าเพียงเสี้ยววินาที และ post-masking บังเสียงที่ตามหลังได้นานกว่า

3) ช่วยลดจำนวนบิตอย่างไร ในขั้นที่ 3 psychoacoustic model จะนำ threshold of hearing รวมกับผลของ frequency และ temporal masking มาคำนวณเป็นเส้น masking threshold ของแต่ละย่านความถี่ จากนั้นจัดสรรบิตดังนี้

  • ย่านที่สัญญาณอยู่ใต้ threshold หูไม่ได้ยินอยู่แล้ว จึงไม่ต้องเก็บ (0 bit)
  • ย่านที่สัญญาณอยู่เหนือ threshold ใช้บิตเท่าที่จำเป็นให้ quantization noise ยังต่ำกว่า masking threshold เพราะ noise ที่อยู่ใต้เส้นนั้นจะถูก masker บังจนไม่ได้ยิน ถ้า noise ดังเกิน threshold จึงค่อยเพิ่มบิต
  • เนื่องจากบิต 1 บิตลด noise ได้ราว 6 dB (SQNR ≈ 6.02N + 1.76) ถ้า masking ยก threshold ของย่านหนึ่งขึ้น 18 dB ก็ลดได้ราว 3 บิตต่อ sample ในย่านนั้น ผลรวมทำให้บีบอัดได้ประมาณ 10:1 (เช่น MP3, AAC)

4) ขั้นที่ 1: Filter bank 32 ตัว แยกสัญญาณเป็น 32 ย่านความถี่ ทำให้รู้ว่าในขณะนั้นย่านไหนมีเสียงดัง (masker) และย่านใกล้เคียงไหนมีเสียงเบา (maskee) ซึ่งจำเป็นต่อการวิเคราะห์ frequency masking และยังทำให้จัดสรรบิตแยกเป็นรายย่านได้ ถ้าไม่แยกความถี่ก็ต้องใช้บิตเท่ากันทั้งสัญญาณ

5) ขั้นที่ 2: จัดกลุ่ม 12 samples ต่อย่าน สร้างหน้าต่างเวลาสั้น ๆ (1 เฟรม = 32 × 12 = 384 samples) ทำให้เห็นว่าภายในช่วงเวลานั้น sample ไหนเป็นเสียงดัง และ sample ไหนเกิดก่อนหรือหลังมัน จึงวิเคราะห์ temporal masking ได้ นอกจากนี้แต่ละกลุ่มมี scale factor (ระดับสัญญาณสูงสุดในกลุ่ม) และจัดสรรบิตใหม่ได้ทุกเฟรมตามเสียงที่เปลี่ยนไป

สรุป ขั้นที่ 1 ให้มิติความถี่ ขั้นที่ 2 ให้มิติเวลา ขั้นที่ 3 ใช้ทั้งสองมิติหาว่าส่วนไหนหูไม่ได้ยิน แล้วใช้บิตกับส่วนที่ได้ยินเท่านั้น สุดท้ายขั้นที่ 4 บันทึกจำนวนบิตที่ใช้ scale factor และข้อมูลที่ quantize แล้ว

Audio Processing: Filter, EQ, Reverb, Vocoder, Auto-tune

เตรียมคำตอบสั้นของแต่ละเทคนิค โจทย์อาจถามทีละตัวหรือให้เปรียบเทียบ

Filter ต่างจาก Equalizer อย่างไร

ทั้งสองเปลี่ยน frequency response ของเสียงเหมือนกัน แต่ต่างที่เป้าหมาย Filter ใช้ตัดหรือเน้นย่านความถี่ มี 4 แบบ: low-pass (เก็บความถี่ต่ำกว่า threshold), high-pass (เก็บสูงกว่า), band-pass (เก็บเฉพาะช่วง) และ band-stop/notch (ตัดเฉพาะช่วง) เช่น เสียงพัดลม 600 Hz ใช้ band-stop ตัดออกโดยไม่กระทบเสียงพูดย่านอื่น

Equalizer ใช้ปรับสมดุลความดังระหว่างย่านความถี่ให้ฟังดี มี 2 แบบ: graphic EQ แบนด์ความถี่ตายตัว เลื่อนเพิ่มลดแต่ละแบนด์ และ parametric EQ ไม่มีแบนด์ตายตัว ปรับพารามิเตอร์ (ความถี่กลาง ความกว้าง ระดับ) ได้เอง

Reverb และการรับรู้ขนาดห้อง

จงอธิบายองค์ประกอบของ reverb และแต่ละองค์ประกอบช่วยให้รับรู้สภาพแวดล้อมได้อย่างไร

ในธรรมชาติเราได้ยินทั้งเสียงตรงจากแหล่งกำเนิดและเสียงที่สะท้อนจากพื้นผิวรอบตัว จึงรับรู้พื้นที่และบรรยากาศได้ (soundscape) เสียงที่อัดใกล้ไมค์มากจะแทบไม่มีเสียงสะท้อน จึงต้องเติม reverb ให้ฟังเป็นธรรมชาติ ประกอบด้วย 3 ส่วน

  1. Direct sound (dry) เสียงตรงที่ไม่ผ่านการสะท้อน บอกทิศทางของแหล่งเสียง
  2. Early reflections เสียงสะท้อนชุดแรก มาถึงหลังเสียงตรง 10–50 ms ช่องว่างระหว่างเสียงตรงกับเสียงสะท้อนแรกบอกขนาดห้อง (ช่องว่างยาว = ห้องใหญ่) และมีผลต่อความชัดและความดัง
  3. Late reverberant sound (decay, reverberant tail) มาหลัง ~50 ms เกิดจากการสะท้อนหลายพื้นผิวหลายครั้ง มาจากทุกทิศ ซับซ้อนที่สุด เวลาที่มันจางหายบอกขนาดห้องเช่นกัน

HLS / DASH: Adaptive Streaming

CH11 — หัวข้อที่มีแผนภาพในสไลด์ 2 รูป โอกาสออกสูง

จงอธิบายการทำงานของ HLS (หรือ DASH) ตั้งแต่ต้นทางจนถึงผู้ชม และอธิบายว่าทำไมจึงเรียกว่า adaptive streaming
Audio/video input→Media encoder (H.264 + AAC)→ MPEG-2 TS →Stream segmenter→Origin web server: index + segments→ HTTP / CDN →Client

นิยาม HLS (HTTP Live Streaming, Apple) เป็น video segmented streaming ที่ใช้ได้ทั้ง live และ on-demand วิดีโอถูกแบ่งเป็นไฟล์ย่อย ส่งผ่าน HTTP ธรรมดา และรองรับ adaptive bitrate

ฝั่ง server

  1. วิดีโอจากกล้องถูก encode เป็น H.264 (ภาพ) และ AAC หรือ MP3 (เสียง) ได้ MPEG-2 transport stream
  2. HLS server segment สตรีมเป็นชิ้นสั้น ๆ (ไม่กี่วินาที) adapt ทำเวอร์ชันหลาย bitrate/ความละเอียด และ package ไฟล์ ได้ segment นามสกุล .ts (MPEG-2 TS) หรือ .m4s (fragmented MP4)
  3. สร้าง index file (manifest) รูปแบบ M3U (.m3u8) ระบุรายการ segment ความยาว และลำดับการเล่น
  4. เก็บ index และ segment บน origin web server แล้วกระจายผ่าน CDN ไปยังเซิร์ฟเวอร์ใกล้ผู้ชม

ฝั่ง client โหลด manifest ก่อน จึงรู้ว่ามี segment และ bitrate ใดบ้าง → ขอ segment ทีละชิ้นผ่าน HTTP → วัดความเร็วเน็ตและระดับ buffer → เลือก bitrate ของ segment ถัดไป (เน็ตเร็วโหลด 1080p เน็ตช้าลดเป็น 480p) → ต่อ segment เล่นต่อเนื่อง

ทำไมเรียก adaptive เพราะทุก segment มีหลายคุณภาพ และ client เลือกคุณภาพใหม่ได้ทุกครั้งที่ขอ segment ภาพจึงปรับตามสภาพเครือข่ายแทนที่จะหยุดกระตุก

ข้อดีของการใช้ HTTP ใช้ web server และ CDN ที่มีอยู่แล้ว cache segment ได้เหมือนไฟล์เว็บทั่วไป เล่นได้แทบทุกอุปกรณ์ · ข้อจำกัด latency สูงกว่า เพราะต้องรอ segment ครบชิ้น จึงไม่เหมาะกับ ultra-low latency

Live Streaming: RTMP → Media Server → CDN → HLS/DASH

CH11 — แผนภาพ RTMP-compatible camera และ ingest/egress

จงอธิบายเส้นทางของวิดีโอในการถ่ายทอดสด (เช่น จาก OBS ไปยัง YouTube) ว่าแต่ละช่วงใช้ protocol ใดและทำไม
กล้อง / OBS (encoder)→ RTMP (ingest) →Media server: transcode + package→ egress →CDN→ HLS / DASH (delivery) →ผู้ชมหลายอุปกรณ์

1) Ingest encoder เช่น OBS หรือกล้องที่รองรับ RTMP เข้ารหัสภาพเสียงแบบ real-time แล้วส่งขึ้นไปยัง media server ด้วย ingestion protocol ซึ่งปัจจุบันนิยม RTMP (Real-time Messaging Protocol จาก Macromedia/Adobe) เพราะรองรับ normal, low และ ultra-low latency ถ้าต้องการเข้ารหัสใช้ RTMPS

2) Media server รับสตรีมแล้วทำ transcoding คือ re-encode ด้วย codec ที่เหมาะกับการส่ง และทำหลายความละเอียด/bitrate จากนั้น packaging แบ่ง segment และสร้าง manifest สำหรับ HLS/DASH

3) CDN ถ้าคนดูน้อย media server ส่งเองได้ แต่ถ้าคนดูมากต้องใช้ CDN ซึ่งเป็นเครือข่ายเซิร์ฟเวอร์กระจายทั่วโลก cache segment ไว้ เมื่อผู้ชมกด play คำขอจะถูกส่งไปเซิร์ฟเวอร์ที่ใกล้ที่สุด ลดภาระ server หลักและลด latency

4) Delivery ผู้ชมรับผ่าน HLS/DASH บน HTTP แบบ adaptive bitrate

ทำไมขาขึ้นใช้ RTMP แต่ขาลงไม่ใช้ RTMP latency ต่ำและ encoder รองรับแพร่หลาย จึงเหมาะกับการส่งจากต้นทางจุดเดียว แต่มีปัญหา device compatibility (เดิมอิง Flash) ขาลงที่ต้องส่งให้ผู้ชมจำนวนมากหลายอุปกรณ์จึงใช้ HLS/DASH ที่เล่นได้ทุกที่และ cache บน CDN ได้

HTML เป็น descriptive markup language กำหนดโครงสร้างเอกสารด้วย element ที่มี tag เปิด-ปิด และ attribute (ชื่อ + ค่า เช่น href="…") HTML รุ่นแรกอิง SGML แต่ปัจจุบัน WHATWG กำหนดมาตรฐานขึ้นเองแบบ living standard CSS กำหนดการแสดงผล (presentation) ของเนื้อหา

เมื่อเบราว์เซอร์อ่าน HTML จะสร้าง DOM คือโครงสร้างข้อมูลแบบ tree ในหน่วยความจำ แต่ละ node แทน element หรือข้อความ (text node เป็น leaf เสมอ) DOM API คือวิธีมาตรฐานให้ JavaScript อ่านและแก้ DOM เช่น document.getElementById() หรือ querySelectorAll("p") ทำให้หน้าเว็บโต้ตอบและเปลี่ยนแปลงได้ เช่น ควบคุม <video> <audio> วาดบน <canvas> จัดการฟอร์ม drag & drop และเชื่อมกับ Web Storage, Web Workers, WebSocket

Renderer process ของเบราว์เซอร์สร้าง main thread ซึ่งทำงานต่อกันเป็นลำดับ: parse HTML → สร้าง DOM → รัน JavaScript → คำนวณ layout → paint pixel แต่ละขั้นต้องรอผลขั้นก่อนหน้า ถ้า JavaScript ทำงานหนักนาน ขั้นอื่นและการตอบสนองผู้ใช้ก็ต้องรอ หน้าเว็บจึงค้าง

Web worker คือ thread เพิ่มสำหรับรัน script แยกจาก main thread ปล่อยให้ main thread ดูแล UI อย่างเดียว ข้อดีคือ UI ไม่ค้างและใช้ CPU หลายคอร์ได้ดีขึ้น เหมาะกับงานมัลติมีเดียเพราะ (1) การประมวลผลภาพ เสียง วิดีโอใช้การคำนวณสูง และ (2) ต้องตอบสนองทันทีหรือ real-time เช่น แอปใส่ฟิลเตอร์วิดีโอที่ประมวลผลทุกเฟรมใน worker ขณะที่ปุ่มควบคุมยังกดได้ลื่น

ส่วนเสริมอื่น: WebGL ใช้ OpenGL ES เรนเดอร์ 2D/3D ใน canvas ด้วย GPU · WebSocket/SSE รับข้อมูลจาก server โดยไม่ต้อง polling · Web Storage local/session ราว 5–10 MB ต่อ origin

element / tag / attribute · descriptive markup · DOM = data structure (tree) · DOM API = สะพาน JS ↔ DOM · CSS = presentation · renderer process / main thread ทำงานเป็นลำดับ · web worker = thread แยก, UI ไม่ค้าง, multi-core · WebGL = GPU
